# 07-P0-workflow-engine.md

## 1. 文档目的

本文档用于定义 **企业级低代码平台 v1.2 P0 阶段的流程审批引擎模块需求**。

流程审批引擎是低代码平台中承接“表单提交、业务流转、节点处理、状态更新、权限控制、审计留痕”的核心模块。P0 阶段流程引擎不追求完整 BPMN 标准兼容，也不追求复杂流程自动化，而是优先满足企业内部管理应用中最高频的审批场景：

```text
合同审批
费用报销审批
采购申请审批
行政人事审批
台账数据审核
```

本文档面向产品、架构、前端、后端、测试、实施以及后续 AI 生成系统架构、数据库设计、API 文档、代码骨架、测试用例和开发任务拆解使用。

---

## 2. 模块定位

流程审批引擎用于让实施顾问、业务管理员和 IT 管理员通过可视化方式配置业务流程，并让业务用户在运行端完成流程发起、审批、驳回、撤回、作废和日志追踪。

P0 阶段流程审批引擎定位为：

> **面向企业内部管理应用的轻量审批流引擎，支持常见审批链、条件分支、抄送、节点处理人规则、节点字段权限和流程日志。**

流程审批引擎不是孤立模块，它需要与以下模块协同：

```text
数据对象建模 → 提供业务对象、状态字段、人员字段、部门字段、金额字段等流程条件依据
表单设计器 → 提供流程发起表单、审批表单、查看表单和节点字段权限载体
视图/台账 → 展示流程状态、审批结果、流程数据和待处理业务数据
权限系统 → 控制谁能发起、处理、查看、撤回、作废、管理流程
发布运行时 → 按已发布流程定义创建流程实例和任务实例
审计日志 → 记录流程定义变更、流程实例操作和审批意见
模板中心 → 内置合同、报销、采购流程模板
基础看板 → 统计待审批数、已完成数、流程耗时和状态分布
```

P0 阶段流程引擎重点解决：

```text
1. 可以通过可视化方式配置审批流程。
2. 表单提交后可以自动发起流程。
3. 流程可以按部门、角色、人员、上级和表单字段动态找人。
4. 流程可以按金额、类型、部门等字段做条件分支。
5. 审批人可以在待办中处理任务，并填写审批意见。
6. 流程节点可以控制字段可见、只读、可编辑和必填。
7. 流程状态可以回写业务数据状态。
8. 流程全过程必须有日志和审计记录。
9. 设计态流程修改不能影响已发布流程实例。
```

## 4. 业务目标

P0 流程审批引擎需要达成以下目标：

| 目标 | 说明 |
|---|---|
| 可视化配置 | 搭建者通过拖拽节点和配置属性完成审批流程设计。 |
| 表单驱动 | 业务用户提交表单时自动发起流程，流程与业务数据绑定。 |
| 常见审批覆盖 | 支持合同、报销、采购中的直线审批、部门审批、法务/财务审批和归档。 |
| 条件分支 | 支持按金额、类型、部门、字段值路由到不同审批节点。 |
| 灵活找人 | 支持指定用户、角色、部门、发起人上级、字段引用等处理人规则。 |
| 节点字段权限 | 支持不同节点对表单字段配置可见、只读、可编辑、必填。 |
| 状态联动 | 流程节点推进后可更新业务数据状态。 |
| 运行可追踪 | 流程实例、任务、审批意见、耗时和操作日志可查询。 |
| 发布隔离 | 草稿流程修改不影响已发布流程版本和运行中的流程实例。 |
| 可扩展 | 为 P1/P2 的会签、并行、加签、转交、消息通知、动作流预留扩展点。 |

## 5. P0 范围

P0 流程审批引擎必须支持以下能力。

### 5.1 流程定义管理

| 功能 | P0 说明 |
|---|---|
| 创建流程 | 在应用内为指定业务对象创建流程定义。 |
| 编辑流程 | 编辑流程名称、编码、描述、绑定对象、触发方式、节点和连线。 |
| 启用/停用流程 | 停用后不能新发起流程，历史实例仍可查看。 |
| 复制流程 | 可复制已有流程作为新流程草稿。 |
| 删除流程 | 删除进入回收站或标记为已删除，已发布历史版本和历史实例保留。 |
| 流程版本 | 每次发布应用或流程时生成流程版本，运行实例绑定创建时的流程版本。 |
| 流程校验 | 发布前校验节点、连线、处理人、条件、表单绑定和权限配置完整性。 |

### 5.2 流程设计器

| 功能 | P0 说明 |
|---|---|
| 画布设计 | 支持在画布中拖拽节点、连接节点、调整位置。 |
| 节点属性面板 | 右侧属性面板配置节点名称、处理人、表单权限、超时预留、状态回写等。 |
| 连线属性 | 条件分支连线可配置条件表达式和优先级。 |
| 校验提示 | 设计器显示未配置处理人、孤立节点、无结束节点、条件冲突等问题。 |
| 预览流程图 | 支持以只读方式预览流程链路。 |
| 保存草稿 | 设计态保存草稿，不影响运行态。 |

### 5.3 P0 节点类型

| 节点类型 | P0 说明 |
|---|---|
| 开始节点 | 流程发起入口，每个流程必须且只能有一个开始节点。 |
| 审批节点 | 由一个或多个规则确定审批人，审批人处理通过或驳回。P0 按单人/多人任一处理策略简化实现，复杂会签后置。 |
| 抄送节点 | 向指定人员、角色、部门或字段引用人员生成抄送记录。P0 抄送人只读查看，不需要处理。 |
| 条件分支 | 根据业务字段条件进入不同后续节点。支持金额、枚举、部门、人员、状态等基础条件。 |
| 结束节点 | 流程正常结束或非正常结束的终点，每个流程至少一个结束节点。 |

### 5.4 P0 流程操作

| 操作 | 操作人 | P0 说明 |
|---|---|---|
| 发起 | 有发起权限的用户 | 提交绑定流程的表单后创建流程实例和首个任务。 |
| 审批通过 | 当前节点审批人 | 当前任务通过，流程进入下一节点。 |
| 审批驳回 | 当前节点审批人 | 驳回至发起人，业务数据状态更新为已驳回或退回修改。 |
| 撤回 | 发起人 | 在流程未结束且未被限制时撤回流程。P0 默认只允许在流程未最终通过前撤回。 |
| 作废 | 发起人或管理员 | 将流程作废，业务数据进入已作废状态，保留日志。 |
| 查看轨迹 | 发起人、审批人、抄送人、管理员、授权用户 | 查看流程图、当前节点、历史节点、意见和耗时。 |
| 查看待办 | 审批人 | 查看当前需要自己处理的流程任务。 |
| 查看已办 | 审批人 | 查看自己处理过的流程任务。 |
| 查看我的申请 | 发起人 | 查看自己发起的流程实例。 |

### 5.5 P0 处理人规则

| 规则 | P0 说明 |
|---|---|
| 指定用户 | 明确选择一个或多个用户作为处理人。 |
| 指定角色 | 指定角色下的用户作为处理人。 |
| 指定部门 | 指定部门负责人或部门内指定角色作为处理人。 |
| 发起人上级 | 根据组织架构中的直属上级或部门负责人确定处理人。 |
| 字段引用 | 通过表单中的人员字段或部门字段确定处理人。 |
| 发起人本人 | 可用于提交确认、归档确认等节点。 |

### 5.6 P0 条件分支能力

P0 支持基础条件表达式，不支持复杂脚本。

| 条件类型 | 示例 |
|---|---|
| 金额比较 | 合同金额 > 100000，报销总额 <= 5000。 |
| 枚举判断 | 合同类型 = 销售合同，费用类型 = 差旅费。 |
| 部门判断 | 所属部门 = 销售部。 |
| 人员判断 | 申请人 = 当前用户，负责人不为空。 |
| 日期判断 | 申请日期在某个时间范围内。 |
| 状态判断 | 数据状态 = 草稿 / 待审批 / 已驳回。 |
| 组合条件 | 金额 > 100000 且 合同类型 = 采购合同。 |

P0 条件表达式原则：

```text
1. 仅允许基于当前业务对象字段、系统字段和流程变量判断。
2. 不允许执行任意代码。
3. 所有条件必须可视化配置。
4. 条件必须可被后端安全解析和执行。
5. 多条条件分支需要配置优先级。
6. 未命中任何条件时必须有默认分支或发布校验失败。
```

### 5.7 P0 表单绑定

流程必须绑定业务对象和表单。

| 绑定内容 | P0 说明 |
|---|---|
| 绑定对象 | 一个流程绑定一个主业务对象，例如合同、报销单、采购申请。 |
| 发起表单 | 用户提交该表单后发起流程。 |
| 审批表单 | 审批人处理任务时使用的表单，可与发起表单相同，也可配置节点字段权限。 |
| 查看表单 | 发起人、抄送人、管理者查看流程详情时使用只读表单。 |
| 状态字段 | 流程需要回写业务对象状态字段。 |
| 审批意见 | 流程审批意见作为流程日志保存，P0 不强制写入业务对象字段。 |

### 5.8 P0 节点字段权限

P0 必须支持基础节点字段权限。

| 权限 | 说明 |
|---|---|
| 可见 | 审批节点可以看到指定字段。 |
| 不可见 | 审批节点隐藏指定字段。 |
| 只读 | 审批节点可查看字段但不能修改。 |
| 可编辑 | 审批节点可以修改指定字段。 |
| 必填 | 审批节点处理前必须填写指定字段。 |

典型示例：

```text
合同流程
- 发起人可编辑合同名称、合同金额、相对方、附件。
- 部门负责人可查看全部业务字段，只能填写审批意见。
- 法务节点可编辑法务意见、风险等级。
- 财务节点可编辑付款方式、预算科目。
- 归档节点可上传盖章合同附件。
```

### 5.9 P0 流程日志

流程全过程必须留痕。

| 日志内容 | P0 说明 |
|---|---|
| 流程发起 | 记录发起人、时间、表单数据 ID、流程版本。 |
| 节点进入 | 记录进入节点、进入时间、候选处理人。 |
| 任务分配 | 记录任务处理人、任务状态、创建时间。 |
| 审批操作 | 记录通过、驳回、撤回、作废、意见、附件预留。 |
| 节点离开 | 记录离开节点、处理耗时、下一个节点。 |
| 流程结束 | 记录结束时间、结束状态、总耗时。 |
| 异常日志 | 记录找不到处理人、条件不匹配、权限不足等异常。 |

### 5A.1 P0 功能点描述统一要求

本章节中的每一个 P0 功能点都必须满足以下描述规范，后续 AI 生成页面、API、数据库、测试用例和开发任务时必须直接引用功能编号。

| 描述项 | 要求 |
|---|---|
| 功能编号 | 使用 `P0-模块缩写-序号`，序号三位递增。 |
| 所属分类 | 标明该功能归属的业务分类，便于研发分包。 |
| 用户角色 | 标明主要使用者，不能只写“用户”。 |
| 业务目标 | 说明为什么需要该功能。 |
| 前置条件 | 说明功能执行前必须存在的数据、权限或状态。 |
| 输入内容 | 说明页面、接口或配置需要输入哪些字段。 |
| 处理逻辑 | 说明服务端、前端或运行时需要执行的关键逻辑。 |
| 输出结果 | 说明功能执行后产生什么数据、状态或页面变化。 |
| 权限要求 | 说明该功能需要经过哪些权限校验。 |
| 审计要求 | 说明是否需要写入审计日志以及记录内容。 |
| 异常处理 | 说明常见失败场景及系统反馈。 |
| 验收标准 | 说明测试可以如何判断该功能完成。 |

### 5A.2 P0 功能点优先级规则

| 优先级 | 含义 | 处理原则 |
|---|---|---|
| P0-Must | 没有该功能，主业务闭环不可运行。 | 必须随 P0 首版交付。 |
| P0-Should | 没有该功能，主业务闭环仍可运行，但交付体验明显下降。 | 原则上纳入 P0，资源紧张时可降级但必须保留入口。 |
| P0-Guardrail | 不是直接业务功能，但用于安全、审计、发布稳定性。 | 必须纳入 P0，不可后补。 |

| 用户角色 | 实施顾问、应用管理员 |
| 业务目标 | 为三大样板应用提供可直接使用的审批流。 |
| 前置条件 | 对象、表单、角色已初始化。 |
| 输入内容 | 应用模板初始化参数。 |
| 处理逻辑 | 创建合同审批、费用报销审批、采购申请审批流程草稿或已发布模板。 |
| 输出结果 | 三个样板流程定义。 |
| 权限要求 | 模板安装和流程创建权限。 |
| 审计要求 | 记录模板生成流程。 |
| 异常处理 | 缺少角色或字段时生成失败并列出缺失项。 |
| 验收标准 | 安装合同模板后可看到“合同审批流程”。 |

### 5A.5 P0 流程引擎完成定义 Definition of Done

```text
1. 可以创建、编辑、停用、软删除流程定义。
2. 可以通过画布配置开始、审批、抄送、条件分支、结束节点。
3. 审批节点可以配置指定用户、角色、部门、部门负责人和人员字段引用。
4. 条件分支可以基于金额、类型、部门等字段路由。
5. 表单提交可以发起流程，并生成待办任务。
6. 审批人可以通过、驳回，并填写意见。
7. 发起人可以撤回，管理员可以作废。
8. 流程轨迹可以展示节点、处理人、动作、意见和耗时。
9. 流程状态可以回写业务数据状态。
10. 流程发布生成版本快照，运行中实例不受草稿修改影响。
11. 所有关键操作必须写入审计日志。
12. 合同、报销、采购三个样板流程可完整跑通。
```

## 6. P0 不做范围

为避免范围失控，以下能力不进入 P0：

| 能力 | 处理方式 |
|---|---|
| 完整 BPMN 标准兼容 | P0 只做业务审批流，BPMN 后续评估。 |
| 并行网关 | P1/P2。P0 可以在 DSL 预留节点类型。 |
| 会签 | P1/P2。P0 不承诺全员通过、比例通过等复杂策略。 |
| 或签 | P1/P2。P0 可简化为多人候选任一处理。 |
| 加签 | P1/P2。 |
| 转交/转办 | P1/P2。 |
| 委托审批 | P1/P2。 |
| 子流程 | P2。 |
| 流程 SLA | P2。P0 可预留超时字段但不强制实现。 |
| 流程仿真 | P2。 |
| 流程版本差异对比 | P2。P0 只保留版本记录和回滚。 |
| 复杂脚本条件 | P1/P2。P0 只支持可视化条件表达式。 |
| 自动动作节点 | P1 动作流能力承接。P0 可预留节点类型但不实现复杂动作。 |
| 外部系统回调审批 | P1/P2 由连接器和动作流承接。 |
| 原生 App 审批 | P0 只支持 PC 和移动端 H5 自适应。 |

## 7. 核心概念

| 概念 | 说明 |
|---|---|
| 流程定义 | 流程设计态配置，包括节点、连线、条件、处理人规则和节点权限。 |
| 流程版本 | 发布后的不可变流程定义快照，流程实例创建时绑定一个版本。 |
| 流程节点 | 流程中的开始、审批、抄送、条件分支、结束等节点。 |
| 流程连线 | 节点之间的流转关系，可配置条件和优先级。 |
| 流程实例 | 用户发起一次流程后生成的运行实例。 |
| 任务实例 | 某个节点分配给处理人的待办任务。 |
| 抄送记录 | 给抄送人的只读通知和查看记录。 |
| 流程变量 | 流程运行过程中可用于条件判断和日志记录的变量。 |
| 业务数据 | 流程绑定的对象记录，例如一条合同、一张报销单。 |
| 流程状态 | 流程实例当前状态，例如审批中、已通过、已驳回。 |
| 业务状态 | 业务数据的状态字段，例如草稿、审批中、已归档。 |
| 节点字段权限 | 当前节点处理表单时字段可见、只读、可编辑、必填规则。 |

## 8. 核心用户故事

### 8.1 实施顾问配置合同审批流程

```text
作为实施顾问，
我希望在合同管理应用中配置“部门负责人 → 法务 → 财务 → 归档”的审批流程，
并按合同金额决定是否进入财务审批，
以便客户可以通过平台完成合同审批和归档。
```

验收要点：

```text
1. 可为合同对象创建流程定义。
2. 可配置部门负责人、法务、财务、归档节点。
3. 可配置合同金额条件分支。
4. 可配置法务节点编辑法务意见字段。
5. 流程通过后合同状态更新为待归档或已归档。
```

### 8.2 业务管理员配置报销审批流程

```text
作为业务管理员，
我希望配置“员工提交 → 直属上级审批 → 财务审核 → 归档”的报销流程，
以便员工提交报销后可以自动流转给对应负责人和财务。
```

验收要点：

```text
1. 可通过发起人上级规则找到直属上级。
2. 可通过指定角色找到财务审批人。
3. 财务节点可编辑付款状态、财务备注。
4. 员工可查看自己发起的流程状态。
```

### 8.3 采购申请按金额走不同审批链

```text
作为采购管理员，
我希望采购金额低于 5000 元时由部门负责人审批，
高于 5000 元时额外进入财务或管理层审批，
以便不同金额采购走不同审批链。
```

验收要点：

```text
1. 可配置金额阈值条件。
2. 可配置默认分支。
3. 条件命中后流程进入正确节点。
4. 流程轨迹展示实际经过的节点。
```

### 8.4 审批人处理待办

```text
作为审批人，
我希望在待办中心看到需要自己处理的审批任务，
查看表单、附件、流程轨迹，并填写审批意见后通过或驳回，
以便及时处理业务申请。
```

验收要点：

```text
1. 审批人只能看到分配给自己的待办任务。
2. 审批页展示业务表单、流程轨迹、历史意见和操作按钮。
3. 通过或驳回后任务状态更新。
4. 操作写入流程日志和审计日志。
```

### 8.5 发起人撤回流程

```text
作为流程发起人，
我希望在发现提交内容有误时可以撤回尚未完成的流程，
以便修改后重新提交。
```

验收要点：

```text
1. 仅发起人或管理员可撤回。
2. 已完成、已作废的流程不可撤回。
3. 撤回后当前待办任务关闭。
4. 业务数据状态更新为已撤回或草稿。
5. 撤回操作写入日志。
```

## 9.4 节点配置

## 9.4.1 开始节点

### 定位

开始节点代表流程入口。

### P0 配置项

| 配置项 | 必填 | 说明 |
|---|---|---|
| 节点名称 | 是 | 默认“开始”。 |
| 发起权限 | 是 | 哪些用户、角色、部门可以发起。 |
| 发起表单 | 是 | 绑定表单。 |
| 初始业务状态 | 是 | 提交后业务数据状态，例如审批中。 |

### 业务规则

```text
1. 每个流程必须有且只能有一个开始节点。
2. 开始节点必须连接至少一个后续节点。
3. 没有发起权限的用户不能看到提交/发起入口。
4. 表单提交前需要先执行表单校验、字段权限校验和对象新增权限校验。
```

## 9.4.2 审批节点

### 定位

审批节点用于生成待办任务，由审批人处理通过或驳回。

### P0 配置项

| 配置项 | 必填 | 说明 |
|---|---|---|
| 节点名称 | 是 | 例如部门负责人审批、法务审批、财务审核。 |
| 处理人规则 | 是 | 指定用户、角色、部门、上级、字段引用。 |
| 任务标题模板 | 否 | 例如“合同审批：${合同名称}”。 |
| 审批表单 | 否 | 默认使用绑定表单，可按节点权限渲染。 |
| 字段权限 | 是 | 节点字段可见、只读、可编辑、必填规则。 |
| 通过后状态 | 否 | 当前节点通过后回写业务状态。 |
| 驳回后状态 | 是 | 驳回后业务状态，例如已驳回。 |
| 是否允许驳回 | 是 | P0 默认允许驳回。 |
| 审批意见是否必填 | 否 | 可配置驳回时意见必填。 |

### P0 处理策略

P0 不做复杂会签/或签，但需要定义多人处理时的简化策略：

```text
1. 如果处理人规则返回 1 人，则生成 1 个任务。
2. 如果处理人规则返回多人，P0 默认使用“任一人处理即通过/驳回该节点”的策略。
3. 该策略应在节点配置中显示为“多人候选，任一处理”。
4. 会签、全员通过、比例通过、依次审批后续扩展。
```

### 业务规则

```text
1. 审批节点必须配置有效处理人规则。
2. 流程运行时如果找不到处理人，应进入异常状态，并提示管理员处理。
3. 审批人只能处理分配给自己的待办。
4. 已处理任务不能重复处理。
5. 驳回后，当前节点后续未完成任务应关闭。
6. 审批意见、处理时间、处理结果必须记录。
```

## 9.4.3 抄送节点

### 定位

抄送节点用于让相关人员获得流程查看权限。

### P0 配置项

| 配置项 | 必填 | 说明 |
|---|---|---|
| 节点名称 | 是 | 例如抄送申请人部门负责人。 |
| 抄送人规则 | 是 | 指定用户、角色、部门、字段引用。 |
| 抄送时机 | 是 | P0 默认流程到达该节点时抄送。 |
| 查看权限 | 是 | 抄送人是否可查看表单、附件、流程轨迹。 |

### 业务规则

```text
1. 抄送节点不阻塞流程推进。
2. 抄送人不需要处理任务。
3. 抄送记录应出现在“抄送我的”或流程详情中。
4. 抄送人只能查看授权字段和流程信息。
```

## 9.4.4 条件分支

### 定位

条件分支用于根据字段值决定后续流程路径。

### P0 配置项

| 配置项 | 必填 | 说明 |
|---|---|---|
| 节点名称 | 是 | 例如金额判断。 |
| 条件组 | 是 | 一组或多组条件。 |
| 条件优先级 | 是 | 多条条件按优先级执行。 |
| 默认分支 | 是 | 未命中条件时走默认分支。 |

### 条件配置方式

条件配置应可视化，不允许用户直接写任意代码。

```text
字段        操作符        值
合同金额    大于          100000
合同类型    等于          采购合同
所属部门    等于          当前用户部门
```

支持操作符：

```text
等于
不等于
大于
大于等于
小于
小于等于
包含
不包含
为空
不为空
属于
不属于
```

### 业务规则

```text
1. 条件分支必须至少有一个条件分支和一个默认分支。
2. 条件字段必须来自当前绑定对象或允许引用的系统字段。
3. 条件中使用的字段被删除或停用时，发布校验失败。
4. 多条件命中时按优先级选择第一条。
5. 未命中任何条件且无默认分支时，流程进入异常状态；设计态发布前应阻止这种情况。
```

## 9.4.5 结束节点

### 定位

结束节点表示流程完成、驳回结束、撤回结束或作废结束。

### P0 配置项

| 配置项 | 必填 | 说明 |
|---|---|---|
| 节点名称 | 是 | 例如审批完成、已驳回结束。 |
| 结束类型 | 是 | 通过结束、驳回结束、作废结束等。 |
| 业务状态回写 | 是 | 回写业务数据状态。 |

### 业务规则

```text
1. 每个流程至少有一个结束节点。
2. 结束节点不能有后续节点。
3. 流程进入结束节点后，流程实例状态变为终态。
4. 终态流程不允许继续审批。
```

## 10. 流程运行需求

## 10.1 流程发起

### 触发条件

P0 流程发起由表单提交触发：

```text
用户填写表单
→ 点击提交
→ 表单校验
→ 权限校验
→ 保存业务数据
→ 创建流程实例
→ 创建首个任务或抄送记录
→ 更新业务状态为审批中
→ 写入流程日志和审计日志
```

### 业务规则

```text
1. 用户必须有对象新增权限和流程发起权限。
2. 表单必填、校验、字段权限必须先通过。
3. 业务数据保存成功后再创建流程实例。
4. 流程实例创建失败时，业务数据应回滚或标记为草稿/异常，避免孤儿数据。
5. 流程实例创建成功后，业务数据必须记录 workflow_instance_id 或可反查流程实例。
```

## 10.2 待办生成

待办任务由流程进入审批节点时生成。

任务字段至少包括：

| 字段 | 说明 |
|---|---|
| 任务标题 | 根据模板生成。 |
| 所属流程实例 | workflow_instance_id。 |
| 所属节点 | workflow_node_id。 |
| 处理人 | assignee_user_id。 |
| 任务状态 | 待处理、已通过、已驳回、已关闭。 |
| 创建时间 | 任务生成时间。 |
| 到达时间 | 节点进入时间。 |
| 处理时间 | 审批人处理时间。 |
| 审批意见 | 审批人填写。 |

### 待办展示字段

```text
任务标题
应用名称
业务对象名称
申请人
申请部门
当前节点
发起时间
到达时间
流程状态
优先级预留
```

## 10.3 审批处理

### 审批页内容

审批人打开待办后，应看到：

```text
1. 业务表单内容。
2. 当前节点名称。
3. 当前节点可执行操作：通过、驳回。
4. 审批意见输入框。
5. 节点字段权限控制后的可编辑字段。
6. 附件查看区域。
7. 流程轨迹。
8. 历史审批意见。
```

### 通过操作

```text
审批人点击通过
→ 校验任务是否属于当前用户
→ 校验任务状态是否待处理
→ 校验节点必填字段
→ 保存节点可编辑字段变更
→ 保存审批意见
→ 更新任务状态为已通过
→ 判断下一节点
→ 生成下一节点任务/抄送/结束流程
→ 更新业务状态
→ 写入日志
```

### 驳回操作

P0 驳回策略建议：

```text
1. P0 默认驳回至发起人。
2. 驳回后流程实例状态变为已驳回。
3. 当前及后续未处理任务关闭。
4. 业务数据状态变为已驳回或退回修改。
5. 发起人可基于已驳回数据重新编辑并再次提交，具体由表单/视图模块支持。
```

P0 暂不支持：

```text
驳回到指定历史节点
驳回后从被驳回节点继续
驳回到任意节点
```

这些能力后续作为 P1/P2 扩展。

## 10.4 撤回

### 撤回规则

```text
1. 发起人可以撤回自己发起且未终结的流程。
2. 管理员可以撤回授权范围内的异常流程。
3. 已通过、已作废、已撤回的流程不能再次撤回。
4. 撤回后所有待处理任务关闭。
5. 业务数据状态更新为已撤回或草稿。
6. 撤回必须填写撤回原因，可配置为必填。
```

## 10.5 作废

### 作废规则

```text
1. 作废用于终止不再继续处理的流程。
2. 默认发起人和管理员可以作废，具体受权限控制。
3. 作废后流程实例进入终态。
4. 作废后业务数据状态更新为已作废。
5. 作废操作不可直接恢复，只能通过管理员特殊操作或重新发起业务数据。
```

## 10.6 流程轨迹

流程轨迹需要展示：

```text
流程节点图
已完成节点
当前节点
未到达节点
驳回/撤回/作废节点
每个节点处理人
处理结果
处理时间
处理意见
节点耗时
```

P0 可以采用简化展示：

```text
流程图 + 时间线
```

## 11. 状态模型

## 11.1 流程定义状态

```text
草稿
→ 已发布
→ 已停用
→ 已删除
```

| 状态 | 说明 |
|---|---|
| 草稿 | 可编辑，未生效。 |
| 已发布 | 可被运行端发起。 |
| 已停用 | 不可新发起，历史实例可处理和查看。 |
| 已删除 | 软删除，不在正常列表显示。 |

## 11.2 流程实例状态

```text
草稿
→ 审批中
→ 已通过
→ 已驳回
→ 已撤回
→ 已作废
→ 异常
```

| 状态 | 说明 | 是否终态 |
|---|---|---|
| 草稿 | 已保存但未提交。 | 否 |
| 审批中 | 流程正在运行。 | 否 |
| 已通过 | 流程正常结束通过。 | 是 |
| 已驳回 | 审批人驳回。 | 是 |
| 已撤回 | 发起人撤回。 | 是 |
| 已作废 | 发起人或管理员作废。 | 是 |
| 异常 | 找不到处理人、条件错误、系统异常等。 | 否 |

## 11.3 任务状态

```text
待处理
→ 已通过
→ 已驳回
→ 已关闭
→ 已取消
```

| 状态 | 说明 |
|---|---|
| 待处理 | 等待处理人审批。 |
| 已通过 | 处理人通过。 |
| 已驳回 | 处理人驳回。 |
| 已关闭 | 因驳回、撤回、作废或其他人已处理而关闭。 |
| 已取消 | 流程异常或节点重算导致取消。 |

## 11.4 业务数据状态建议

P0 建议业务对象统一内置或配置状态字段：

```text
草稿
审批中
已通过
已驳回
已撤回
已作废
已归档
```

不同样板应用可扩展业务状态：

| 应用 | 状态示例 |
|---|---|
| 合同管理 | 草稿、审批中、已驳回、待归档、已归档、已作废。 |
| 费用报销 | 草稿、审批中、已驳回、待付款、已付款、已作废。 |
| 采购申请 | 草稿、审批中、已驳回、待采购、已完成、已作废。 |

## 12. 权限规则

流程权限必须与平台权限系统协同。

## 12.1 发起权限

发起权限控制谁可以提交某个流程。

配置维度：

```text
指定用户
指定角色
指定部门
应用使用者
对象新增权限用户
```

规则：

```text
1. 用户必须同时具备应用访问权限、对象新增权限和流程发起权限。
2. 没有发起权限时，不显示提交按钮或提示无权限。
3. 发起权限变更必须写入审计日志。
```

## 12.2 处理权限

处理权限控制谁可以审批任务。

规则：

```text
1. 只有任务 assignee 或候选处理人可以处理任务。
2. 管理员可查看但默认不代处理，代处理后续扩展。
3. 停用用户不能处理任务，需要管理员处理异常任务。
4. 用户离职/停用后的待办进入异常或待管理员处理状态。
```

## 12.3 查看权限

流程查看权限来源：

```text
发起人
当前审批人
历史审批人
抄送人
应用管理员
平台管理员
数据权限授权用户
```

规则：

```text
1. 用户只能查看授权范围内流程实例。
2. 查看流程详情时仍需执行字段级权限。
3. 抄送人只读查看，不可处理。
4. 已办人可以查看自己处理过的流程记录。
```

## 12.4 节点字段权限

节点字段权限优先级建议：

```text
系统安全限制 > 字段级权限 > 流程节点字段权限 > 表单默认配置
```

说明：

```text
1. 如果字段被系统级安全限制为不可见，节点不能覆盖为可见。
2. 如果字段对当前用户无字段查看权限，节点不能显示。
3. 节点可在基础字段权限范围内进一步配置只读、可编辑、必填。
4. 审批时只能提交当前节点允许编辑的字段。
```

## 12.5 管理权限

流程管理权限包括：

```text
创建流程
编辑流程
发布流程
停用流程
删除流程
查看全部实例
处理异常实例
查看流程日志
导出流程数据预留
```

P0 建议由应用管理员和平台管理员拥有。

## 13. 业务规则

## 13.1 流程结构规则

```text
1. 每个流程必须有一个开始节点。
2. 每个流程至少有一个结束节点。
3. 开始节点不能有入线。
4. 结束节点不能有出线。
5. 审批节点必须配置处理人规则。
6. 条件分支必须配置默认分支。
7. 所有节点必须从开始节点可达。
8. 不能存在无法到达结束节点的路径。
9. P0 不允许无限循环。
```

## 13.2 发布校验规则

发布流程前必须校验：

```text
1. 绑定对象存在且未删除。
2. 绑定表单存在且已发布或可随应用发布。
3. 状态字段存在且类型合法。
4. 节点和连线结构合法。
5. 所有审批节点处理人规则完整。
6. 条件分支字段存在且类型兼容。
7. 节点字段权限引用字段存在。
8. 流程编码在应用内唯一。
9. 所有引用角色、部门、用户仍有效。
```

## 13.3 流程运行规则

```text
1. 流程实例创建后绑定流程版本，不随流程草稿变化。
2. 流程每次流转必须在事务或一致性机制内完成状态更新和日志记录。
3. 任务处理必须防止重复提交。
4. 审批按钮需要做幂等处理。
5. 条件分支计算失败时，流程实例进入异常状态。
6. 找不到处理人时，流程实例进入异常状态并通知管理员预留。
7. 所有流程动作必须记录操作人、时间、结果和来源。
```

## 13.4 流程与业务数据规则

```text
1. 一条业务数据同一时间 P0 默认只能有一个运行中的主流程。
2. 业务数据被流程占用时，普通编辑需要受流程状态和字段权限控制。
3. 流程通过、驳回、撤回、作废时必须回写业务数据状态。
4. 删除业务数据前必须校验是否存在运行中流程。
5. 业务数据恢复后，历史流程日志仍需可查。
```

## 14. 异常处理

| 异常场景 | P0 处理方式 |
|---|---|
| 找不到处理人 | 流程实例进入异常状态，记录错误，管理员可查看。P1 支持重新指定处理人。 |
| 条件无匹配分支 | 设计态发布前应阻止；运行时发生则进入异常状态。 |
| 审批人被停用 | 任务不可处理，流程进入异常或待管理员处理。 |
| 表单字段被删除 | 未发布草稿校验失败；历史流程按历史版本渲染。 |
| 角色/部门被删除 | 发布校验失败；运行中找人失败进入异常。 |
| 重复点击通过 | 后端幂等处理，第二次返回任务已处理。 |
| 审批时无权限 | 拒绝操作并记录安全日志。 |
| 保存字段失败 | 审批操作整体失败，任务状态不变。 |
| 流程推进失败 | 回滚本次处理或标记异常，不能出现任务已完成但流程未推进的状态。 |
| 日志写入失败 | 关键日志失败应阻止核心操作或进入异常，不能无痕执行关键操作。 |

## 17. 三大样板应用流程需求

## 17.1 合同管理流程

### 流程目标

验证平台对主表、附件、金额条件分支、法务/财务节点字段权限、归档状态和流程日志的支持。

### 推荐流程

```text
合同起草
→ 部门负责人审批
→ 法务审批
→ 条件分支：是否需要财务审批
    ├── 是：财务审批
    └── 否：归档
→ 归档
→ 结束
```

### 条件规则示例

```text
如果 合同金额 >= 100000 或 合同类型 = 采购合同
则进入财务审批
否则进入归档
```

### 节点字段权限示例

| 节点 | 可编辑字段 | 只读字段 |
|---|---|---|
| 发起人 | 合同名称、合同类型、相对方、金额、附件、付款计划 | 系统编号、状态 |
| 部门负责人 | 审批意见 | 合同基础字段、附件 |
| 法务审批 | 法务意见、风险等级 | 合同基础字段、金额、附件 |
| 财务审批 | 付款方式、预算科目、财务意见 | 合同基础字段、法务意见 |
| 归档 | 盖章合同附件、归档备注 | 合同基础字段、审批意见 |

### 验收标准

```text
1. 可配置合同审批流程。
2. 合同提交后生成流程实例。
3. 金额条件能正确进入财务审批或跳过财务审批。
4. 法务节点只能编辑法务相关字段。
5. 归档节点可以上传盖章合同附件。
6. 审批通过后合同状态变为已归档或待归档。
7. 合同详情页可查看完整流程轨迹。
```

## 17.2 费用报销流程

### 流程目标

验证平台对子表金额汇总、直属上级审批、财务审核、附件查看、财务字段权限和移动端审批的支持。

### 推荐流程

```text
员工提交报销
→ 直属上级审批
→ 财务审核
→ 付款确认/归档
→ 结束
```

P0 可以将付款确认并入财务审核或归档节点。

### 条件规则示例

```text
如果 报销总金额 > 5000
则可进入部门负责人审批或财务主管审批（P1/P2 可扩展）
P0 默认使用直属上级 → 财务审核链路
```

### 节点字段权限示例

| 节点 | 可编辑字段 | 只读字段 |
|---|---|---|
| 发起人 | 报销事由、费用明细、发票附件 | 报销状态、审批字段 |
| 直属上级 | 审批意见 | 报销明细、金额、附件 |
| 财务审核 | 财务备注、付款状态、付款日期 | 报销明细、审批意见 |
| 归档 | 归档备注 | 全部业务字段 |

### 验收标准

```text
1. 员工可提交报销单并上传发票附件。
2. 系统根据组织架构找到直属上级。
3. 财务角色用户收到财务审核待办。
4. 财务节点可编辑付款状态和财务备注。
5. 报销通过后状态更新为待付款或已付款。
6. 发起人可查看自己的报销流程状态和历史意见。
```

## 17.3 采购申请流程

### 流程目标

验证平台对采购明细子表、供应商关联、金额条件分支、多角色审批和采购台账状态的支持。

### 推荐流程

```text
采购申请提交
→ 部门负责人审批
→ 条件分支：采购金额是否超过阈值
    ├── 是：财务审批
    └── 否：采购执行
→ 采购执行/归档
→ 结束
```

### 条件规则示例

```text
如果 采购总金额 > 5000
则进入财务审批
否则进入采购执行
```

## 24. 给 AI 生成代码/设计的提示

后续 AI 或研发基于本文档生成代码、架构、API、数据库和测试用例时，必须遵守以下约束：

```text
1. 不要把流程写死为合同、报销、采购三条固定流程，必须做成元数据驱动。
2. 所有流程定义必须可序列化为 JSON DSL。
3. 流程设计态和运行态必须隔离。
4. 流程实例必须绑定发布时的流程版本。
5. P0 只实现开始、审批、抄送、条件分支、结束节点。
6. P0 不实现完整 BPMN、会签、并行、加签、转交、委托、子流程。
7. 条件表达式必须使用安全可解析的结构化表达式，不允许任意脚本执行。
8. 任务处理接口必须幂等，防止重复审批。
9. 所有流程操作必须校验 tenant_id、app_id、用户权限和任务状态。
10. 所有关键流程操作必须写流程日志和审计日志。
11. 节点字段权限必须与表单运行时、字段权限系统协同。
12. 流程通过、驳回、撤回、作废必须回写业务数据状态。
13. 流程异常不能静默失败，必须有异常状态和可查询日志。
14. P0 移动端只做 H5 自适应，不做原生 App 特性。
15. 代码实现优先保证合同、报销、采购三类样板流程可稳定运行。
```
