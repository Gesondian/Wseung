# 09-P0-release-runtime.md

## 1. 文档目的

本文档用于定义 **企业级低代码平台 v1.2 P0 阶段的发布、版本与运行时模块需求**。

发布、版本与运行时是低代码平台从“可配置”走向“可稳定使用”的关键模块。低代码平台不能让设计态配置直接影响线上业务，否则字段、表单、流程、权限的任何修改都可能导致运行端异常。因此 P0 阶段必须明确区分：

```text
设计态
→ 发布态
→ 运行态
```

本文档面向产品、架构、前端、后端、测试、实施以及后续 AI 生成系统架构、数据库设计、API 文档、代码骨架、测试用例和开发任务拆解使用。

本文档重点说明：

```text
1. 应用从草稿配置到正式运行的发布机制。
2. 应用版本、元数据快照和回滚规则。
3. 运行时如何读取已发布元数据并渲染应用。
4. 运行时如何执行表单、视图、流程、权限和审计。
5. 发布校验、发布失败、运行异常等关键异常处理。
6. P0 阶段不做灰度发布、环境流水线和复杂 DevOps，但预留后续扩展。
```

---

## 2. 模块定位

发布、版本与运行时模块用于解决以下问题：

```text
设计态正在编辑的配置，不能直接影响线上用户。
每一次正式发布都必须形成可追溯版本。
运行端必须只读取已发布版本。
发布前必须校验元数据完整性。
发布失败不得影响当前线上稳定版本。
已发布版本必须支持查看、停用和回滚。
运行时必须统一处理权限、状态、校验、流程和审计。
```

P0 阶段该模块定位为：

> **低代码平台设计态到运行态的稳定交付通道，以及已发布应用的元数据解释执行运行底座。**

它不是完整 DevOps 平台，也不是复杂发布流水线系统。P0 阶段重点保证：

```text
1. 应用配置可发布。
2. 应用发布后可运行。
3. 草稿修改不影响线上版本。
4. 出错可回滚到上一稳定版本。
5. 运行端按已发布元数据执行。
6. 全链路有审计和日志。
```

## 3. 目标用户

| 用户角色 | 使用目标 |
|---|---|
| 实施/配置顾问 | 完成应用配置后执行发布，验证运行端是否符合预期。 |
| 业务管理员 | 查看应用发布状态、发布版本和运行效果。 |
| IT 管理员 | 控制应用上线、停用、回滚和版本治理。 |
| 应用设计者 | 在设计态持续修改数据对象、表单、视图、流程和权限。 |
| 普通业务用户 | 在运行端访问已发布应用，提交数据、查看台账、处理流程。 |
| 审批人/流程处理人 | 在运行端处理已发布流程版本产生的待办任务。 |
| 运维人员 | 查看发布日志、运行日志、异常日志和回滚记录。 |
| 开发者 | 根据发布模型、版本快照和运行时元数据协议实现服务。 |
| AI 开发助手 | 根据本文档生成发布状态机、运行时服务、API、数据库表、测试用例和开发任务。 |

## 4. 业务目标

P0 发布、版本与运行时模块需要达成以下目标。

| 目标 | 说明 |
|---|---|
| 设计运行隔离 | 草稿配置修改不影响已发布应用。 |
| 发布前校验 | 发布前校验应用、对象、字段、表单、视图、流程、权限是否满足运行条件。 |
| 版本快照 | 每次发布生成独立版本和完整元数据快照。 |
| 版本可追溯 | 可查看发布人、发布时间、版本号、变更摘要和发布结果。 |
| 支持回滚 | 可回滚到上一稳定版本。 |
| 运行时解析 | 运行端只读取已发布元数据包并动态渲染页面和执行业务规则。 |
| 权限强制校验 | 所有运行时访问都必须经过服务端权限校验。 |
| 流程版本锁定 | 已发起流程实例绑定发起时的流程版本，不受后续发布影响。 |
| 运行日志可查 | 运行错误、发布错误、回滚操作、关键数据操作可追踪。 |
| 私有化优先 | P0 优先支持私有化单租户部署，预留 tenant_id 支持后续 SaaS。 |

## 5. P0 范围

P0 发布、版本与运行时必须支持以下能力。

### 5.1 设计态、发布态、运行态分离

| 能力 | P0 说明 |
|---|---|
| 设计态 | 应用配置编辑区，允许修改对象、字段、表单、视图、流程、权限、模板等配置。 |
| 发布态 | 将设计态配置校验、冻结、打包为应用版本。 |
| 运行态 | 面向最终用户使用，只读取已发布版本。 |
| 草稿隔离 | 草稿修改不影响当前运行版本。 |
| 历史版本保留 | 至少保留已发布版本记录和上一稳定版本快照。 |

P0 必须保证：

```text
运行端不得直接读取草稿配置。
设计态保存不等于发布。
发布成功后才影响新进入运行端的用户。
发布失败不得影响当前运行版本。
```

---

### 5.2 应用发布

应用发布是把设计态配置变成运行态可用版本的过程。

P0 应用发布必须支持：

| 功能 | P0 说明 |
|---|---|
| 发布入口 | 应用设计器顶部提供“发布”入口。 |
| 发布说明 | 发布时必须填写或自动生成发布说明。 |
| 发布校验 | 发布前执行完整性校验。 |
| 发布版本号 | 发布成功后生成版本号。 |
| 发布快照 | 发布成功后冻结应用元数据快照。 |
| 发布结果 | 显示发布成功或失败原因。 |
| 发布记录 | 保存发布人、发布时间、版本号、变更摘要、发布状态。 |
| 运行端更新 | 发布成功后运行端读取最新已发布版本。 |

发布触发者：

```text
应用所有者
应用管理员
拥有发布权限的应用设计者
平台管理员
```

普通业务用户不得发布应用。

---

### 5.3 发布前校验

发布前必须校验应用是否具备运行条件。

P0 发布校验至少包括：

| 校验项 | 校验规则 |
|---|---|
| 应用基础信息 | 应用名称、编码、状态、所属空间必须有效。 |
| 数据对象 | 至少存在一个可发布对象；对象编码不可重复。 |
| 字段定义 | 字段编码不可重复；字段类型必须有效；必填字段必须有合法配置。 |
| 系统字段 | 创建人、创建时间、更新人、更新时间、状态等系统字段必须完整。 |
| 表单 | 绑定对象必须存在；组件绑定字段必须存在；必填字段必须可输入。 |
| 视图 | 绑定对象必须存在；显示列和筛选字段必须存在。 |
| 流程 | 已启用流程必须存在开始节点、至少一个审批节点和结束节点。 |
| 流程连线 | 节点连线必须可达，不能存在断裂主链路。 |
| 条件分支 | 条件字段必须存在，条件表达式必须可解析。 |
| 处理人规则 | 审批节点必须能解析出处理人规则。 |
| 权限策略 | 应用访问权限、对象权限、数据权限和字段权限必须存在默认策略。 |
| 菜单入口 | 发布到运行端的页面必须有可访问入口。 |
| 模板引用 | 引用的模板、组件、字段和流程必须存在。 |

校验结果必须分为：

```text
阻断错误：必须修复后才能发布。
警告提示：允许继续发布，但需要提示风险。
```

阻断错误示例：

```text
对象没有主字段。
表单组件绑定了已删除字段。
流程审批节点没有处理人。
条件分支字段不存在。
权限策略缺失导致运行端无人可访问。
```

警告提示示例：

```text
某个字段未加入任何表单。
某个视图未配置筛选条件。
某个应用未配置基础看板。
某个流程未配置抄送人。
```

---

### 5.4 应用版本管理

P0 必须提供应用版本记录。

每个发布版本至少包含：

| 字段 | 说明 |
|---|---|
| version_id | 版本 ID。 |
| app_id | 应用 ID。 |
| version_no | 版本号，例如 v1、v2、v3 或 1.0.0。 |
| version_name | 版本名称，可选。 |
| release_note | 发布说明。 |
| release_status | 发布状态。 |
| released_by | 发布人。 |
| released_at | 发布时间。 |
| metadata_snapshot_id | 元数据快照 ID。 |
| is_current | 是否当前运行版本。 |
| previous_version_id | 上一版本 ID。 |
| rollback_from_version_id | 如果是回滚版本，记录来源版本。 |

P0 版本能力包括：

```text
查看版本列表
查看版本详情
查看当前运行版本
查看发布说明
查看发布结果
回滚到上一稳定版本
查看回滚记录
```

P0 不要求支持任意版本差异对比，但应预留变更摘要字段。

---

### 5.5 元数据快照

发布成功后必须生成 **元数据快照**。

元数据快照是运行时的唯一可信配置来源。

P0 元数据快照应包含：

```text
应用基础信息
应用菜单
数据对象定义
字段定义
表单定义
视图定义
流程定义
流程节点和连线
权限策略
字段权限
数据权限
按钮/操作权限
基础看板配置
模板来源信息
运行端页面入口
```

P0 元数据快照必须满足：

```text
1. 可序列化为 JSON。
2. 可按 app_id + version_id 查询。
3. 发布后不可修改。
4. 运行时只读取已发布快照。
5. 回滚时可以重新指向历史快照。
6. 可用于后续应用导出、迁移和私有化交付。
```

---

### 5.6 版本回滚

P0 必须支持回滚到上一稳定版本。

回滚规则：

| 规则 | 说明 |
|---|---|
| 回滚对象 | 应用当前运行版本。 |
| 回滚目标 | P0 至少支持回滚到上一稳定版本。 |
| 回滚影响 | 新访问运行端的用户读取回滚后的版本。 |
| 历史数据 | 不删除已产生业务数据。 |
| 流程实例 | 已发起流程实例继续使用发起时绑定的流程版本。 |
| 审计日志 | 必须记录回滚人、时间、来源版本、目标版本、原因。 |
| 权限控制 | 只有应用管理员、发布管理员或平台管理员可执行回滚。 |

回滚不得做以下事情：

```text
不得删除业务数据。
不得篡改历史流程实例。
不得修改历史发布快照。
不得直接覆盖草稿配置。
```

回滚后系统应生成一条新的运行版本记录，或将当前运行版本指针切换到历史稳定版本。具体实现可由架构阶段确定，但必须保证可审计、可追溯。

---

### 5.7 应用停用与恢复运行

P0 应支持应用停用。

应用停用后：

```text
普通用户不能访问运行端应用。
应用数据不删除。
流程新实例不能发起。
已存在待办可按配置禁止处理或仅允许查看。
应用管理员仍可进入设计态。
应用可重新启用。
停用、启用必须记录审计日志。
```

应用停用适用场景：

```text
应用需要下线维护。
应用模板验证失败。
业务应用暂时不用。
应用存在严重配置问题。
```

P0 可不做计划停用、自动停用和灰度停用。

### 5.8 运行时渲染

运行时负责根据已发布元数据动态渲染应用。

P0 运行时至少需要支持：

| 运行时页面 | P0 说明 |
|---|---|
| 应用入口 | 展示用户有权限访问的应用菜单和页面。 |
| 列表/台账页 | 按视图配置渲染列、筛选、排序、按钮和数据。 |
| 新增表单页 | 按表单配置渲染可填写表单。 |
| 编辑表单页 | 按表单和权限配置渲染可编辑字段。 |
| 详情页 | 按表单或详情配置展示业务数据。 |
| 审批处理页 | 按流程节点字段权限渲染审批表单和意见区。 |
| 流程轨迹页 | 展示流程节点、处理记录、意见和状态。 |
| 基础看板页 | 按已发布看板配置展示指标卡和基础图表。 |

运行时必须统一处理：

```text
元数据加载
权限校验
字段显隐
字段只读
字段必填
字段校验
默认值计算
数据查询
数据提交
流程发起
任务处理
审计日志
异常提示
```

---

### 5.9 运行时元数据加载

运行时加载规则：

```text
1. 根据 tenant_id + app_id 查找当前已发布版本。
2. 根据 version_id 读取元数据快照。
3. 根据当前用户解析应用访问权限。
4. 根据页面/对象/表单/流程上下文解析可用配置。
5. 按权限过滤菜单、按钮、字段和数据。
6. 渲染页面并绑定运行时 API。
```

运行时不得：

```text
直接读取草稿表单。
直接读取草稿流程。
直接读取草稿权限。
绕过发布快照读取最新配置。
将客户端传入字段直接写入数据库而不校验元数据。
```

### 5.10 运行时数据提交

运行时数据提交包括：

```text
新增数据
编辑数据
删除/作废数据
发起流程
审批处理
驳回
撤回
导入数据
```

P0 数据提交规则：

| 规则 | 说明 |
|---|---|
| 服务端校验 | 所有字段必填、类型、格式、权限都必须服务端校验。 |
| 字段白名单 | 只能提交当前表单和当前权限允许写入的字段。 |
| 版本绑定 | 数据提交时应记录当前应用版本或表单版本。 |
| 状态更新 | 流程提交、审批通过、驳回等操作需更新业务状态。 |
| 审计记录 | 新增、编辑、删除、审批等关键操作必须写日志。 |
| 幂等处理 | 避免重复提交导致重复数据或重复审批。 |

---

### 5.11 运行时权限校验

运行时所有访问必须经过权限系统校验。

P0 运行时至少校验：

```text
应用访问权限
菜单/页面访问权限
对象查看权限
对象新增权限
对象编辑权限
对象删除/作废权限
数据范围权限
字段可见权限
字段编辑权限
流程发起权限
任务处理权限
审批意见提交权限
导入导出权限
看板访问权限
```

运行时权限校验必须遵循：

```text
默认拒绝。
服务端强制校验。
客户端只负责展示优化。
字段越权提交必须拒绝。
数据越权访问必须拒绝。
```

---

### 5.12 运行时流程执行

运行时流程执行必须读取已发布流程定义。

P0 流程运行规则：

| 场景 | 规则 |
|---|---|
| 发起流程 | 绑定当前已发布流程版本。 |
| 处理任务 | 按任务实例绑定的流程版本执行。 |
| 流程实例 | 不因后续流程重新发布而改变路径。 |
| 条件分支 | 使用实例运行时数据计算条件。 |
| 节点字段权限 | 使用流程节点绑定的表单权限快照。 |
| 流程日志 | 每次处理都记录节点、处理人、意见、时间和结果。 |

关键原则：

```text
新发布流程只影响新发起实例。
历史流程实例不自动迁移。
运行中流程不读取流程草稿。
流程回滚不影响已运行流程实例的历史轨迹。
```

---

### 5.13 发布记录与运行日志

P0 必须记录以下日志：

| 日志类型 | 说明 |
|---|---|
| 发布日志 | 发布人、版本、时间、发布说明、校验结果、发布状态。 |
| 回滚日志 | 回滚人、来源版本、目标版本、回滚原因、时间。 |
| 停用/启用日志 | 操作人、操作时间、应用状态变化。 |
| 运行错误日志 | 页面渲染失败、元数据解析失败、API 调用失败。 |
| 数据操作日志 | 新增、编辑、删除、作废、导入、导出。 |
| 流程操作日志 | 发起、审批、驳回、撤回、作废。 |
| 权限拒绝日志 | 重要越权访问和字段越权提交。 |

P0 日志应能按以下条件查询：

```text
应用
版本
操作人
操作类型
操作时间
操作结果
关键字
```

## 5A. P0 必做清单详表（执行版）

文档版本：v1.2  
更新日期：2026-05-06  
适用范围：`09-P0-release-runtime.md`  

本章节用于把发布、版本与运行时模块从“能力描述”细化为可研发、可测试、可由 AI 后续生成发布服务、运行时渲染服务、元数据快照、API、数据库表和测试用例的 P0 执行清单。本模块是设计态到运行态的稳定交付通道。


### 5A.1 P0 功能点描述统一要求

本章节中的每一个 P0 功能点都必须满足以下描述规范，后续 AI 生成页面、API、数据库、测试用例和开发任务时必须直接引用功能编号。

| 描述项 | 要求 |
|---|---|
| 功能编号 | 使用 `P0-模块缩写-序号`，序号三位递增。 |
| 所属分类 | 标明该功能归属的业务分类，便于研发分包。 |
| 用户角色 | 标明主要使用者，不能只写“用户”。 |
| 业务目标 | 说明为什么需要该功能。 |
| 前置条件 | 说明功能执行前必须存在的数据、权限或状态。 |
| 输入内容 | 说明页面、接口或配置需要输入哪些字段。 |
| 处理逻辑 | 说明服务端、前端或运行时需要执行的关键逻辑。 |
| 输出结果 | 说明功能执行后产生什么数据、状态或页面变化。 |
| 权限要求 | 说明该功能需要经过哪些权限校验。 |
| 审计要求 | 说明是否需要写入审计日志以及记录内容。 |
| 异常处理 | 说明常见失败场景及系统反馈。 |
| 验收标准 | 说明测试可以如何判断该功能完成。 |

### 5A.2 P0 功能点优先级规则

| 优先级 | 含义 | 处理原则 |
|---|---|---|
| P0-Must | 没有该功能，主业务闭环不可运行。 | 必须随 P0 首版交付。 |
| P0-Should | 没有该功能，主业务闭环仍可运行，但交付体验明显下降。 | 原则上纳入 P0，资源紧张时可降级但必须保留入口。 |
| P0-Guardrail | 不是直接业务功能，但用于安全、审计、发布稳定性。 | 必须纳入 P0，不可后补。 |


### 5A.3 P0 功能分类总览

| 分类编号 | 分类名称 | 分类说明 | 是否 P0 必做 |
|---|---|---|---|
| RR-C01 | 设计态管理 | 设计态配置与运行态隔离。 | 是 |
| RR-C02 | 发布前校验 | 对应用、对象、表单、流程、权限做完整校验。 | 是 |
| RR-C03 | 版本与快照 | 生成不可变发布版本和元数据快照。 | 是 |
| RR-C04 | 发布与回滚 | 发布、失败处理、回滚上一版本。 | 是 |
| RR-C05 | 运行时元数据加载 | 加载已发布版本渲染运行端。 | 是 |
| RR-C06 | 运行时表单/视图/流程执行 | 运行态提交、查询、审批、状态回写。 | 是 |
| RR-C07 | 运行时权限与审计 | 运行态统一鉴权和日志记录。 | 是 |
| RR-C08 | 样板应用运行验收 | 合同、报销、采购可发布并运行。 | 是 |

### 5A.5 P0 发布运行时完成定义 Definition of Done

```text
1. 设计态配置和运行态快照完全隔离。
2. 发布前能校验应用、对象、字段、表单、流程、权限完整性。
3. 发布成功后生成不可变版本和元数据快照。
4. 发布失败不影响当前线上版本。
5. 可以查看版本列表和版本详情。
6. 可以回滚到历史成功版本。
7. 应用停用后普通用户无法访问运行端。
8. 运行端只读取当前已发布版本。
9. 运行态表单、视图、流程、权限均按快照执行。
10. 所有运行态接口必须服务端鉴权。
11. 发布、回滚、停用、数据提交、流程审批均有审计。
12. 合同、报销、采购三个样板应用可发布并完整运行。
```

## 6. P0 不做范围

P0 阶段不做以下内容：

```text
1. 不做灰度发布。
2. 不做蓝绿发布。
3. 不做多环境 Dev/Test/Prod 流水线。
4. 不做复杂 CI/CD。
5. 不做自动化测试流水线。
6. 不做版本差异可视化对比。
7. 不做多人协同编辑冲突合并。
8. 不做应用级依赖拓扑分析。
9. 不做应用包跨环境复杂冲突解决。
10. 不做按租户资源配额控制。
11. 不做 SaaS 多租户运营后台。
12. 不做运行时插件热更新。
13. 不做运行时自动扩容调度。
14. 不做原生 App 发布。
15. 不做完整前端代码生成和代码导出。
```

P0 仅预留以下扩展点：

```text
灰度发布字段预留。
多环境字段预留。
应用导入导出包结构预留。
运行时插件入口预留。
发布审批流程预留。
自动化测试钩子预留。
```

## 7. 核心概念

### 7.1 设计态 Design Time

设计态是应用配置区。

设计态允许修改：

```text
应用信息
数据对象
字段
表单
视图
流程
权限
基础看板
模板配置
菜单入口
```

设计态保存后形成草稿配置，但不会影响运行端。

---

### 7.2 发布态 Release Time

发布态是配置从草稿变为正式版本的过程。

发布态包括：

```text
发布校验
版本号生成
元数据快照生成
运行版本指针切换
发布日志记录
发布结果反馈
```

---

### 7.3 运行态 Runtime

运行态是最终用户实际使用应用的环境。

运行态包括：

```text
访问应用
查看菜单
打开列表
新增数据
编辑数据
查看详情
发起流程
处理任务
查看看板
导入导出
```

运行态必须只基于已发布版本工作。

---

### 7.4 应用版本 App Version

应用版本是一次发布产生的版本记录。

一个应用可以有多个历史版本，但只有一个当前运行版本。

---

### 7.5 元数据快照 Metadata Snapshot

元数据快照是一次发布时冻结的完整配置集合。

运行时读取元数据快照，而不是读取设计态配置。

---

### 7.6 运行版本指针 Current Runtime Version

运行版本指针表示当前运行端使用哪个已发布版本。

发布成功后指针切换到新版本。

回滚后指针切换到历史稳定版本或生成新的回滚版本。

---

### 7.7 稳定版本 Stable Version

稳定版本是发布成功且可正常运行的版本。

P0 回滚至少支持回滚到上一稳定版本。

---

### 7.8 草稿 Draft

草稿是设计态未发布配置。

草稿可以频繁保存，但未发布前不影响运行态。

---

## 8. 用户故事

### 8.1 实施顾问发布合同应用

作为实施顾问，我希望在完成合同对象、合同表单、合同审批流和权限配置后，可以点击发布，让合同管理应用在运行端可用。

验收要点：

```text
发布前系统提示配置校验结果。
发布成功后业务用户可以访问合同应用。
草稿修改不会影响已发布合同应用。
```

---

### 8.2 IT 管理员回滚应用版本

作为 IT 管理员，我希望当新发布版本出现配置问题时，可以快速回滚到上一稳定版本，避免业务中断。

验收要点：

```text
可查看历史发布版本。
可选择上一稳定版本执行回滚。
回滚后运行端恢复旧版本配置。
回滚操作有审计记录。
```

---

### 8.3 业务用户访问运行端应用

作为普通业务用户，我只希望看到自己有权限访问的应用、菜单、数据和字段。

验收要点：

```text
无权限应用不可见。
有权限应用可打开。
字段权限在运行端生效。
数据范围在运行端生效。
```

---

### 8.4 审批人处理已发布流程任务

作为审批人，我希望在待办中处理任务时，看到的是发起时对应流程版本的审批表单和字段权限。

验收要点：

```text
流程重新发布后，已有待办不改变审批路径。
节点字段权限按任务所属流程版本执行。
审批意见和操作记录可追踪。
```

---

### 8.5 应用设计者继续编辑草稿

作为应用设计者，我希望在应用已发布后继续编辑草稿，准备下一次发布，而不影响正在使用的线上应用。

验收要点：

```text
草稿可保存。
运行端仍使用当前已发布版本。
下一次发布成功后才切换运行版本。
```

## 12. 业务规则

### 12.1 设计态不影响运行态

设计态保存仅修改草稿配置，不影响运行端。

只有发布成功后，运行端才读取新版本。

---

### 12.2 发布成功原子性

发布操作必须具备原子性。

```text
元数据快照生成成功
版本记录生成成功
运行版本指针更新成功
发布日志记录成功
```

以上过程任一关键步骤失败，不应切换当前运行版本。

---

### 12.3 发布失败保护

发布失败时必须保持当前运行版本不变。

系统应展示失败原因并记录发布失败日志。

---

### 12.4 当前运行版本唯一

同一应用在同一租户下，只允许存在一个当前运行版本。

---

### 12.5 快照不可变

已发布元数据快照不可编辑。

如果需要修改，必须进入设计态修改草稿并重新发布。

---

### 12.6 流程实例版本锁定

流程实例必须绑定发起时流程版本。

后续流程发布或回滚不影响已存在流程实例。

---

### 12.7 权限快照生效规则

P0 建议权限随应用版本发布生效。

即：

```text
草稿权限修改不影响运行端。
发布后权限修改生效。
```

如果后续需要“权限立即生效”，需在架构阶段单独设计，不属于 P0 默认策略。

---

### 12.8 删除与回收站规则

已发布应用删除后进入回收站。

回收站恢复后：

```text
保留历史版本。
保留当前运行版本指针。
恢复前如果应用已停用，则恢复后仍需按停用状态处理，或由管理员手动启用。
```

具体策略可由回收站模块进一步定义。

---

### 12.9 运行时只信任服务端

运行时客户端提交的数据不能被直接信任。

服务端必须基于已发布元数据重新校验：

```text
字段是否存在
字段是否可写
字段类型是否正确
是否满足必填
是否满足校验规则
是否满足数据权限
是否满足流程任务权限
```

---

## 13. 异常处理

### 13.1 发布校验失败

场景：

```text
流程审批节点没有处理人。
表单组件绑定字段已删除。
视图列引用不存在字段。
权限策略缺失。
```

处理：

```text
阻止发布。
展示错误模块、错误项和修复建议。
记录校验失败日志。
```

---

### 13.2 发布过程中断

场景：

```text
数据库写入失败。
元数据快照生成失败。
服务异常。
```

处理：

```text
不得切换当前运行版本。
标记发布失败。
展示错误信息。
记录发布失败日志。
允许重新发布。
```

---

### 13.3 运行端访问未发布应用

处理：

```text
提示“应用尚未发布”。
普通用户不可进入。
应用管理员可跳转设计态。
```

---

### 13.4 运行端访问已停用应用

处理：

```text
提示“应用已停用”。
普通用户不可继续使用。
管理员可进入应用管理页。
```

---

### 13.5 元数据快照不存在

场景：

```text
版本记录存在但快照丢失。
快照解析失败。
```

处理：

```text
阻止运行端继续渲染。
提示应用配置异常。
记录严重错误日志。
建议管理员回滚上一稳定版本。
```

---

### 13.6 字段越权提交

场景：

```text
用户通过接口提交无权限编辑字段。
用户提交表单中不存在的字段。
用户修改只读字段。
```

处理：

```text
拒绝提交。
返回明确错误码。
记录越权日志。
不得写入数据。
```

---

### 13.7 当前版本运行异常

场景：

```text
运行端页面渲染失败。
流程任务创建失败。
表单提交持续失败。
```

处理：

```text
记录运行错误日志。
提示用户稍后重试或联系管理员。
管理员可回滚上一稳定版本。
```

---

### 13.8 回滚失败

场景：

```text
目标版本不存在。
目标版本快照缺失。
用户无回滚权限。
数据库更新失败。
```

处理：

```text
阻止回滚。
保持当前运行版本不变。
展示失败原因。
记录回滚失败日志。
```

| 发布成功 | 应用、版本号、发布人、发布时间、发布说明、快照 ID。 |

## 21. 验收标准

### 21.1 发布验收

```text
1. 应用管理员可以将配置完整的应用发布为新版本。
2. 发布前系统会执行完整性校验。
3. 存在阻断错误时不能发布。
4. 发布成功后运行端使用最新版本。
5. 发布失败时当前运行版本不受影响。
6. 每次发布都有版本记录和发布日志。
```

---

### 21.2 版本验收

```text
1. 应用管理员可以查看历史版本列表。
2. 可以识别当前运行版本。
3. 可以查看版本发布人、发布时间和发布说明。
4. 至少支持回滚到上一稳定版本。
5. 回滚后运行端读取回滚目标版本。
6. 回滚不删除业务数据。
```

---

### 21.3 运行时验收

```text
1. 普通用户只能访问已发布且有权限的应用。
2. 运行端表单按已发布表单配置渲染。
3. 运行端列表按已发布视图配置渲染。
4. 运行端审批页按任务绑定流程版本渲染。
5. 运行端字段权限和数据权限生效。
6. 字段越权提交被服务端拒绝。
7. 应用停用后普通用户不可访问。
```

---

### 21.4 草稿隔离验收

```text
1. 修改草稿字段后，运行端仍显示旧版本字段。
2. 修改草稿流程后，已发起流程实例不受影响。
3. 修改草稿权限后，未发布前运行端权限不变化。
4. 发布成功后新配置才在运行端生效。
```

---

### 21.5 样板应用验收

```text
1. 合同管理模板发布后可完成合同提交、审批、台账查看。
2. 费用报销模板发布后可完成报销提交、明细填写、财务审批。
3. 采购申请模板发布后可完成采购申请、明细填写、条件审批。
4. 三个模板均可查看发布记录、运行日志和关键审计日志。
5. 三个模板均支持停用和回滚到上一稳定版本。
```

## 23. 给 AI 生成代码/设计的提示

后续 AI 在基于本文档生成架构、数据库、API、前端、后端、测试用例和开发任务时，必须遵循以下约束：

```text
1. 必须区分设计态、发布态、运行态。
2. 运行端只能读取已发布元数据快照。
3. 发布必须是原子操作，失败不得影响当前运行版本。
4. 每次发布必须生成版本记录和元数据快照。
5. 元数据快照发布后不可修改。
6. 回滚不得删除业务数据，不得篡改历史流程实例。
7. 流程实例必须绑定发起时流程版本。
8. 所有运行时接口必须做服务端权限校验。
9. 字段越权提交必须拒绝。
10. 所有发布、回滚、停用、运行异常必须记录审计日志。
11. P0 不做灰度发布、多环境流水线、蓝绿发布和复杂 CI/CD。
12. P0 优先私有化单租户部署，但所有核心表应保留 tenant_id。
13. API、数据库、前端页面应围绕 app_id、version_id、metadata_snapshot_id、runtime_pointer 设计。
14. 不要为每个样板应用写死页面和流程，必须基于元数据驱动运行。
15. 所有设计应能支持合同、费用报销、采购申请三个样板应用发布运行。
```
