# 04-P0-data-modeling.md

## 1. 文档目的

本文档用于定义 **企业级低代码平台 v1.2 P0 阶段的数据对象建模模块需求**。

数据对象建模是低代码平台的核心底座，后续以下模块均依赖本模块：

```text
表单设计器
视图/台账
流程审批
权限系统
发布运行时
Excel 导入导出
模板中心
基础看板
审计日志
```

本文档面向产品、架构、前端、后端、测试、实施以及后续 AI 生成系统架构、数据库设计、API 文档、代码骨架和测试用例使用。

---

## 2. 模块定位

数据对象建模模块用于让业务人员、实施顾问和 IT 管理员通过可视化方式定义业务应用的数据结构。

平台不要求用户理解数据库表、字段、索引、外键等技术概念，而是使用更贴近业务的概念：

```text
业务对象 = 一类业务数据
字段 = 业务对象的属性
子表 = 主对象下的明细数据
关联对象 = 对其他业务对象的引用
状态字段 = 业务数据当前所处状态
```

例如：

```text
合同管理应用
├── 合同对象
│   ├── 合同名称
│   ├── 合同编号
│   ├── 合同金额
│   ├── 相对方
│   ├── 签订日期
│   ├── 合同附件
│   └── 合同状态
├── 合同付款计划子表
└── 客户/供应商关联对象
```

P0 阶段的数据建模模块目标是：

> **支持通过可视化配置创建业务对象、字段、子表和关联关系，并为表单、视图、流程、权限、导入导出和运行时提供统一元数据。**

## 3. 目标用户

| 用户角色 | 使用目标 |
|---|---|
| 实施/配置顾问 | 为客户创建合同、报销、采购等业务对象，并配置字段、子表和关联关系。 |
| 业务管理员 | 根据部门业务需要调整字段、状态、显示名称、校验规则。 |
| IT 管理员 | 管理字段权限、数据权限、对象发布、变更风险和审计。 |
| 开发者 | 基于对象元数据生成 API、运行时数据服务、导入导出能力和后续扩展能力。 |
| AI 开发助手 | 根据本文档生成数据库设计、接口设计、DSL、代码骨架和测试用例。 |

## 4. 业务目标

P0 阶段数据对象建模需要满足以下业务目标：

| 目标 | 说明 |
|---|---|
| 快速建模 | 搭建者可以在无代码情况下创建业务对象和字段。 |
| 支撑样板应用 | 能完整支撑合同管理、费用报销、采购申请三类样板应用。 |
| 支撑主子表 | 能配置报销明细、采购明细、付款计划等明细数据。 |
| 支撑对象关联 | 能建立合同与客户/供应商、采购申请与供应商等关联关系。 |
| 支撑运行时 | 对象发布后，运行端可以基于元数据生成默认 CRUD 能力。 |
| 支撑权限 | 对象、字段、记录均可被权限系统控制。 |
| 支撑发布版本 | 草稿态变更不影响已发布运行态。 |
| 支撑审计 | 对象和字段的创建、修改、删除、发布均可追踪。 |
| 支撑扩展 | 后续可扩展公式字段、复杂关联、动态物理表、数据集和 OLAP。 |

## 5. P0 范围

P0 数据对象建模必须支持以下能力。

| 分类 | 功能点 | P0 要求 |
|---|---|---|
| 对象管理 | 创建业务对象 | 支持在应用内创建对象。 |
| 对象管理 | 编辑业务对象 | 支持修改对象名称、编码、说明、图标、状态等基础信息。 |
| 对象管理 | 删除业务对象 | 支持软删除；删除前校验依赖。 |
| 对象管理 | 对象复制 | 支持复制对象结构，数据是否复制可后续增强，P0 可只复制结构。 |
| 字段管理 | 创建字段 | 支持 P0 字段类型。 |
| 字段管理 | 编辑字段 | 支持修改字段标签、说明、默认值、校验、显示配置等安全属性。 |
| 字段管理 | 删除字段 | 支持软删除，保留历史数据解释能力。 |
| 字段管理 | 字段排序 | 支持在设计态调整字段顺序。 |
| 字段类型 | 基础字段 | 文本、多行文本、数字、金额、日期、日期时间、单选、多选、布尔。 |
| 字段类型 | 组织字段 | 人员、部门。 |
| 字段类型 | 文件字段 | 附件、图片。 |
| 字段类型 | 系统字段 | 自动编号、状态、创建人、创建时间、更新人、更新时间、所属部门。 |
| 关系建模 | 子表 | 支持一对多明细数据。 |
| 关系建模 | 关联对象 | 支持对其他业务对象的单条引用。 |
| 校验规则 | 必填 | 字段可配置必填。 |
| 校验规则 | 唯一 | 字段可配置唯一，P0 仅建议对文本、自动编号等有限类型支持。 |
| 校验规则 | 范围 | 数字、金额、日期支持范围校验。 |
| 校验规则 | 格式 | 文本支持简单正则或内置格式校验。 |
| 默认值 | 静态默认值 | 支持固定值。 |
| 默认值 | 系统默认值 | 当前用户、当前部门、当前时间。 |
| 索引字段 | 高频查询字段 | 支持标记字段参与搜索/筛选/索引。 |
| 导入导出 | 字段映射属性 | 支持配置字段是否参与导入导出。 |
| 发布版本 | 草稿与发布 | 对象和字段配置需经过发布后运行态生效。 |
| 审计日志 | 配置变更审计 | 创建、修改、删除、发布均写审计。 |

## 5A. P0 必做清单详表（执行版）

文档版本：v1.2  
更新日期：2026-05-06  
适用范围：`04-P0-data-modeling.md`  

本章节用于把数据对象建模模块从“能力描述”细化为可研发、可测试、可由 AI 后续生成数据库、API、前端页面、元数据 DSL 和测试用例的 P0 执行清单。数据建模是表单、视图、流程、权限、导入导出、模板和运行时的共同基础。


### 5A.1 P0 功能点描述统一要求

本章节中的每一个 P0 功能点都必须满足以下描述规范，后续 AI 生成页面、API、数据库、测试用例和开发任务时必须直接引用功能编号。

| 描述项 | 要求 |
|---|---|
| 功能编号 | 使用 `P0-模块缩写-序号`，序号三位递增。 |
| 所属分类 | 标明该功能归属的业务分类，便于研发分包。 |
| 用户角色 | 标明主要使用者，不能只写“用户”。 |
| 业务目标 | 说明为什么需要该功能。 |
| 前置条件 | 说明功能执行前必须存在的数据、权限或状态。 |
| 输入内容 | 说明页面、接口或配置需要输入哪些字段。 |
| 处理逻辑 | 说明服务端、前端或运行时需要执行的关键逻辑。 |
| 输出结果 | 说明功能执行后产生什么数据、状态或页面变化。 |
| 权限要求 | 说明该功能需要经过哪些权限校验。 |
| 审计要求 | 说明是否需要写入审计日志以及记录内容。 |
| 异常处理 | 说明常见失败场景及系统反馈。 |
| 验收标准 | 说明测试可以如何判断该功能完成。 |

### 5A.2 P0 功能点优先级规则

| 优先级 | 含义 | 处理原则 |
|---|---|---|
| P0-Must | 没有该功能，主业务闭环不可运行。 | 必须随 P0 首版交付。 |
| P0-Should | 没有该功能，主业务闭环仍可运行，但交付体验明显下降。 | 原则上纳入 P0，资源紧张时可降级但必须保留入口。 |
| P0-Guardrail | 不是直接业务功能，但用于安全、审计、发布稳定性。 | 必须纳入 P0，不可后补。 |

### 5A.4 P0 数据建模必做功能明细

#### P0-DM-001 数据对象列表

| 描述项 | 内容 |
|---|---|
| 所属分类 | DM-C01 |
| 用户角色 | 应用管理员、应用设计者、实施顾问 |
| 业务目标 | 在应用内统一查看和管理业务对象。 |
| 前置条件 | 应用已创建，当前用户具备对象查看权限。 |
| 输入内容 | appId、关键词、状态筛选。 |
| 处理逻辑 | 按 appId 查询对象列表；默认隐藏 deleted；展示对象名称、编码、字段数、状态、更新时间。 |
| 输出结果 | 对象列表页面。 |
| 权限要求 | `entity.view`。 |
| 审计要求 | 查看不审计。 |
| 异常处理 | 应用不存在或无权限时返回错误。 |
| 验收标准 | 用户可在合同应用内看到合同、相对方、付款计划等对象。 |

#### P0-DM-002 创建业务对象

| 描述项 | 内容 |
|---|---|
| 所属分类 | DM-C01 |
| 用户角色 | 应用管理员、应用设计者、实施顾问 |
| 业务目标 | 支持通过可视化方式创建合同、报销单、采购申请等业务对象。 |
| 前置条件 | 应用状态为 draft 或可设计状态。 |
| 输入内容 | 对象名称、对象编码、描述、是否启用流程、是否生成默认表单/视图。 |
| 处理逻辑 | 校验对象编码在 appId 下唯一；创建对象元数据；默认状态 draft；自动生成系统字段。 |
| 输出结果 | 新业务对象、默认字段、可选默认表单和默认视图草稿。 |
| 权限要求 | `entity.create`。 |
| 审计要求 | 记录对象创建。 |
| 异常处理 | 编码重复、应用已停用、无权限时阻止创建。 |
| 验收标准 | 可创建 `contract` 对象，并自动包含创建人、创建时间、状态等系统字段。 |

#### P0-DM-003 编辑业务对象基础信息

| 描述项 | 内容 |
|---|---|
| 所属分类 | DM-C01 |
| 用户角色 | 应用管理员、应用设计者 |
| 业务目标 | 支持调整对象显示名称、描述、排序、图标等基础配置。 |
| 前置条件 | 对象存在且未删除。 |
| 输入内容 | 对象名称、描述、图标、排序、显示配置。 |
| 处理逻辑 | 对象编码 P0 创建后不建议修改；如允许修改，必须校验引用影响。 |
| 输出结果 | 对象基础信息更新。 |
| 权限要求 | `entity.update`。 |
| 审计要求 | 记录修改前后差异。 |
| 异常处理 | 已发布对象修改显示名称不影响历史数据；修改编码需阻止或高风险提示。 |
| 验收标准 | 修改对象显示名称后，表单和视图可显示新名称。 |

#### P0-DM-004 停用业务对象

| 描述项 | 内容 |
|---|---|
| 所属分类 | DM-C01 |
| 用户角色 | 应用管理员、IT 管理员 |
| 业务目标 | 临时停止对象在运行态新增使用，保留历史数据。 |
| 前置条件 | 对象存在且未删除。 |
| 输入内容 | entityId、停用原因。 |
| 处理逻辑 | 状态改为 disabled；运行端不可新增该对象数据；历史数据仍可按权限查看。 |
| 输出结果 | 对象状态变更。 |
| 权限要求 | `entity.disable`。 |
| 审计要求 | 记录状态变更和原因。 |
| 异常处理 | 对象被流程或表单引用时允许停用但需提示影响。 |
| 验收标准 | 停用合同对象后，运行端不可新增合同，但已提交合同仍可查看。 |

#### P0-DM-005 删除业务对象（软删除）

| 描述项 | 内容 |
|---|---|
| 所属分类 | DM-C01 |
| 用户角色 | 应用管理员、IT 管理员 |
| 业务目标 | 删除误建或废弃对象，同时保护历史数据和审计。 |
| 前置条件 | 对象未被已发布表单、视图、流程或模板强依赖；或用户确认风险。 |
| 输入内容 | entityId、删除原因。 |
| 处理逻辑 | 执行软删除；不物理删除业务数据；发布校验需忽略 deleted 对象。 |
| 输出结果 | 对象从设计列表隐藏。 |
| 权限要求 | `entity.delete`。 |
| 审计要求 | 记录删除人、删除时间、依赖关系快照。 |
| 异常处理 | 被已发布版本引用时 P0 建议禁止删除，仅允许停用。 |
| 验收标准 | 删除未发布对象后，不影响已发布应用运行。 |

#### P0-DM-006 字段列表与字段排序

| 描述项 | 内容 |

| 所属分类 | DM-C02 |
| 用户角色 | 应用设计者、实施顾问 |

| 前置条件 | 对象已创建。 |
| 输入内容 | entityId、字段排序。 |

| 输出结果 | 字段列表和排序配置。 |
| 权限要求 | `field.view`、排序需要 `field.update`。 |
| 审计要求 | 排序变化可记录为配置变更审计。 |
| 异常处理 | 系统字段不可删除，不可修改关键属性。 |
| 验收标准 | 可调整报销明细字段在默认表单中的展示顺序。 |

| 描述项 | 内容 |

#### P0-DM-009 停用/删除字段

| 描述项 | 内容 |

| 输出结果 | 字段状态更新或软删除。 |
| 权限要求 | `field.delete`。 |
| 审计要求 | 记录删除原因和依赖关系。 |
| 异常处理 | 字段被流程条件引用时禁止删除。 |
| 验收标准 | 删除未引用字段后，历史 JSON 数据仍保留但运行端不展示。 |

### 5A.5 P0 数据建模完成定义 Definition of Done

```text
1. 可以在应用内创建、编辑、停用、软删除业务对象。

8. 运行态数据可基于通用记录表 + JSONB 存储。
9. 所有对象和字段写操作必须写入审计日志。
10. 所有元数据均可序列化为 JSON DSL，并使用统一公共头。
```

## 6. P0 不做范围

以下能力不进入 P0，需在 PRD 和后续 AI 生成中明确排除：

| 能力 | 处理方式 |
|---|---|
| 动态生成独立物理表 | P0 不做；采用通用记录表 + JSON 数据字段 + 索引字段方案。 |
| 复杂公式字段 | P1/P2；P0 可预留字段类型，不要求完整公式引擎。 |
| 跨对象复杂计算 | P1/P2。 |
| 多对多关系可视化建模 | P1/P2；P0 只做简单关联对象和子表。 |
| 数据血缘分析 | P2。 |
| 完整数据字典治理 | P2。 |
| 字段级加密配置 | P2；P0 可预留脱敏字段权限。 |
| 大规模 OLAP/宽表建模 | P2/P3。 |
| 自动数据库迁移工具 | P1/P2；P0 只做受控元数据变更。 |
| 跨租户对象共享 | P2；P0 单租户优先。 |
| AI 自动建模 | P3；P0 不作为主线。 |

## 7. 核心概念定义

### 7.1 应用 App

应用是数据对象的上级容器。所有对象必须归属于某个应用。

```text
一个应用可以包含多个业务对象。
一个对象不能脱离应用独立存在。
```

### 7.2 业务对象 Object / Entity

业务对象是一类业务数据的抽象，对应合同、报销单、采购申请、供应商、客户等。

业务对象至少包含：

```text
对象名称
对象编码
所属应用
对象说明
对象状态
字段集合
发布版本
权限策略
审计信息
```

### 7.3 字段 Field

字段是业务对象的属性。

例如：

```text
合同名称
合同金额
申请人
申请部门
审批状态
附件
```

字段至少包含：

```text
字段名称
字段编码
字段类型
是否必填
是否唯一
默认值
校验规则
显示配置
权限配置引用
导入导出配置
索引配置
审计信息
```

### 7.4 子表 Subtable

子表用于表达主对象下的一组明细数据。

例如：

```text
费用报销单
└── 报销明细子表
    ├── 费用类型
    ├── 发生日期
    ├── 金额
    └── 说明
```

P0 子表属于主对象的一部分，随主对象创建、编辑、提交和审批。

### 7.5 关联对象 Lookup

关联对象用于引用另一个业务对象中的记录。

例如：

```text
合同对象.客户 = 引用客户对象中的一条记录
采购申请.供应商 = 引用供应商对象中的一条记录
```

P0 仅支持单条引用，多选引用后置。

### 7.6 状态字段 Status

状态字段用于表示业务记录状态。

例如：

```text
草稿
审批中
已通过
已驳回
已撤回
已作废
已归档
```

P0 状态字段需要和流程引擎、视图筛选、数据权限联动。

### 7.7 系统字段 System Fields

每个对象运行时记录必须自动包含系统字段：

```text
tenant_id
app_id
object_id
record_id
record_no
status
created_by
created_dept_id
created_at
updated_by
updated_at
deleted_at
version
```

```text
1. 可在报销单对象下添加报销明细子表。
2. 子表内可配置费用类型、发生日期、金额、说明、附件字段。
```

### 8.3 配置采购申请与供应商关联

作为实施顾问，我希望采购申请对象可以关联供应商对象，以便采购申请中选择已有供应商并在详情页查看供应商信息。

验收标准：

```text

2. 可在采购申请对象中创建供应商关联字段。
3. 运行端可从供应商数据中选择一条记录。
4. 详情页能展示关联供应商名称。
```

### 8.4 配置字段校验

作为业务管理员，我希望合同金额必填且大于 0，以避免无效数据进入流程。

验收标准：

```text
1. 金额字段可配置必填。

3. 运行端提交时校验失败需要提示用户。
```

### 8.5 发布对象变更

作为应用管理员，我希望修改对象字段后先保存为草稿，确认无误后再发布，以避免影响线上用户。

验收标准：

```text
1. 字段变更先进入草稿态。
2. 未发布变更不影响运行态。
3. 发布后运行态可读取新元数据。
4. 发布操作写入审计日志。
```

## 9. 功能点明细

## 9.1 对象管理

### 9.1.1 创建对象

创建对象时需要填写：

| 字段 | 是否必填 | 说明 |
|---|---|---|
| 对象名称 | 是 | 面向用户显示，例如“合同”。 |
| 对象编码 | 是 | 系统内部唯一编码，例如 `contract`。 |
| 所属应用 | 是 | 对象必须归属某个应用。 |
| 对象说明 | 否 | 业务含义说明。 |
| 对象图标 | 否 | 应用设计器和运行端展示使用。 |
| 是否主对象 | 否 | 用于标识样板应用中的核心对象。 |
| 默认状态字段 | 否 | 可自动创建状态字段。 |

业务规则：

```text
1. 同一应用内对象编码不可重复。
2. 对象编码创建后原则上不可修改。
3. 对象名称可修改。
4. 创建对象时自动生成系统字段。
5. 创建对象后默认处于草稿态。
```

### 9.1.2 编辑对象

允许修改：

```text
对象名称
对象说明
```

## 11. 状态流转

### 11.1 对象状态

```text
草稿 → 已发布 → 已修改未发布 → 已停用 → 已删除
   ↑        ↓             ↓
   └────── 回滚 ←─────────┘
```

状态说明：

| 状态 | 说明 |
|---|---|
| 草稿 | 已创建但未发布，仅设计态可见。 |
| 已发布 | 运行态可使用。 |
| 已修改未发布 | 在已发布版本基础上有草稿变更，运行态仍使用旧版本。 |
| 已停用 | 不允许新增数据，历史数据可查看。 |
| 已删除 | 软删除，不再可用，保留恢复或审计能力。 |

### 11.2 字段状态

```text
草稿 → 已发布 → 已修改未发布 → 已停用/软删除
```

字段状态规则：

```text
1. 草稿字段未发布前不进入运行态。
2. 已发布字段删除后只是新版本不再展示，历史版本仍能解释。
3. 系统字段不可停用或删除。
```

### 11.3 对象发布状态

发布动作应将以下配置打包成版本：

```text
对象基础信息
字段定义
字段顺序

字段默认值
字段选项
子表结构
关联关系
系统字段定义
```

发布结果：

```text
1. 生成对象元数据版本。
2. 运行态读取最新发布版本。
3. 草稿态可以继续编辑。
4. 发布操作写入审计日志。
```

## 13. 业务规则

### 13.1 编码规则

对象编码和字段编码建议遵循：

```text
小写字母、数字、下划线
必须以字母开头
同作用域内唯一
创建后不建议修改
```

示例：

```text

contract_amount
supplier_id

```

### 13.2 命名规则

```text
对象名称建议使用业务名词，例如“合同”“报销单”。
字段名称建议使用清晰业务含义，例如“合同金额”“申请部门”。
不建议使用技术名词，例如“表1”“字段A”。
```

### 13.3 系统字段规则

系统字段由平台自动维护，不允许普通搭建者删除。

系统字段包括：

```text
record_id
record_no
status
created_by
created_dept_id
created_at
updated_by
updated_at
deleted_at
version
```

### 13.4 发布规则

```text
1. 未发布对象不能在运行态创建数据。
2. 未发布字段不能被运行态表单使用。
3. 发布前需要执行元数据校验。
4. 校验失败不得发布。
5. 发布失败不得影响当前运行版本。
```

### 13.5 元数据校验规则

发布前至少校验：

```text
对象编码唯一
字段编码唯一
字段类型合法
必填字段配置完整
单选/多选字段至少有一个有效选项
自动编号规则合法
关联对象存在且已发布
子表字段合法
系统字段完整
被表单/视图/流程引用的字段未被非法删除
```

### 13.6 历史数据规则

```text
1. 字段删除不删除历史值。
2. 对象删除不物理删除运行数据。
3. 历史版本应能解释历史记录。
4. 数据导出应按当前权限和当前版本规则处理。
```

## 14. 异常处理

| 异常场景 | 处理要求 |
|---|---|
| 对象编码重复 | 阻止保存，提示重复对象。 |
| 字段编码重复 | 阻止保存，提示重复字段。 |
| 字段类型不合法 | 阻止保存。 |
| 必填字段没有名称或编码 | 阻止保存。 |
| 单选字段没有选项 | 允许保存草稿，但发布时阻止。 |
| 自动编号规则非法 | 阻止发布。 |
| 删除被引用字段 | 阻止删除或提示依赖项。 |
| 删除有数据对象 | 阻止物理删除，允许停用或软删除。 |
| 发布校验失败 | 返回失败项清单。 |
| 发布过程中失败 | 当前运行版本保持不变。 |
| 并发编辑冲突 | 提示配置已被他人修改，要求刷新或合并。 |
| 无权限访问 | 返回权限不足，不泄露敏感对象结构。 |

## 21. 验收标准

### 21.1 对象管理验收

| 验收项 | 通过标准 |
|---|---|
| 创建对象 | 可在应用内创建对象，编码唯一，自动生成系统字段。 |
| 编辑对象 | 可修改对象名称、说明、图标等安全属性。 |
| 删除对象 | 删除前进行依赖校验，有依赖时阻止或提示。 |
| 停用对象 | 停用后不可新增记录，历史记录可查看。 |
| 对象发布 | 发布后运行端可读取对象元数据。 |

### 21.2 字段管理验收

| 验收项 | 通过标准 |
|---|---|
| 创建字段 | 支持 P0 字段类型创建。 |
| 字段唯一 | 同一对象内字段编码不可重复。 |
| 字段校验 | 必填、唯一、范围、格式等规则在前后端生效。 |
| 字段删除 | 删除采用软删除，历史数据不丢失。 |
| 字段依赖 | 被表单、视图、流程、权限引用时需提示依赖。 |

### 21.3 关系建模验收

| 验收项 | 通过标准 |
|---|---|
| 子表 | 可为费用报销和采购申请创建明细子表。 |
| 关联对象 | 可为合同、采购申请创建客户/供应商关联字段。 |
| 关联展示 | 运行端可展示关联对象的显示字段。 |
| 关联删除风险 | 删除目标对象或字段时能提示引用风险。 |

### 21.4 发布与运行验收

| 验收项 | 通过标准 |
|---|---|
| 草稿隔离 | 未发布字段不影响线上运行版本。 |
| 发布校验 | 发布前执行元数据完整性校验。 |
| 发布失败 | 发布失败不得影响当前运行版本。 |
| 历史版本 | 历史记录能根据历史元数据解释字段。 |

## 23. 给 AI 生成代码/设计的提示

后续 AI 在基于本文档生成架构、数据库、API 或代码时，必须遵守以下约束：

```text
1. 不要为每个业务对象直接生成独立物理表，P0 默认采用通用记录表 + JSON 数据字段。
2. 所有对象、字段、子表、关联关系都必须是元数据驱动。
3. 设计态和运行态必须隔离，未发布配置不得影响运行端。
4. 所有对象和字段变更必须写审计日志。
5. 删除对象和字段必须使用软删除，不能直接物理删除历史数据。
6. 对象和字段编码创建后原则上不可修改。
7. 所有运行态接口必须校验应用权限、对象权限、数据权限和字段权限。
8. 所有导入导出能力必须基于字段导入导出配置和权限过滤。
9. P0 不实现复杂公式、完整 ETL、完整 BI、AI 自动建模、多对多关系和动态物理表。
10. 生成数据库设计时必须预留 tenant_id、app_id、created_by、updated_by、deleted_at、version 等公共字段。
11. 生成 API 时必须区分设计态 API 和运行态 API。
12. 生成测试用例时必须覆盖字段类型、依赖删除、发布校验、权限校验和历史数据保留。
```

## 24. 本模块完成定义

当以下条件全部满足时，可认为 P0 数据对象建模模块达到可交付状态：

```text

8. 对象和字段变更可审计。
9. 可支撑合同、报销、采购三个样板应用的数据结构。
```
