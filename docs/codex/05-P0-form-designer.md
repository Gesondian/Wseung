# 05-P0-form-designer.md

## 1. 文档目的

本文档用于定义 **企业级低代码平台 v1.2 P0 阶段的表单设计器模块需求**。

表单设计器是低代码平台中连接“数据对象建模”和“业务用户实际使用”的核心模块。它需要让实施顾问、业务管理员在无代码情况下，基于已定义的数据对象和字段，快速配置数据录入、编辑、查看、审批处理等业务表单。

本文档面向产品、架构、前端、后端、测试、实施以及后续 AI 生成页面设计、数据库设计、API 设计、代码骨架、测试用例和开发任务拆解使用。

---

## 2. 模块定位

表单设计器用于配置业务对象的可视化表单。P0 阶段表单设计器的定位是：

> **基于数据对象元数据，通过拖拽和属性配置生成可发布、可运行、可权限控制、可流程绑定、可多端适配的业务表单。**

表单不是孤立页面，而是低代码平台中的核心元数据资源。它与以下模块强关联：

```text
数据对象建模 → 提供字段、字段类型、校验规则和对象关系
表单设计器 → 配置表单布局、字段绑定、规则、子表和附件
流程审批引擎 → 使用表单作为发起表单和审批表单
权限系统 → 控制字段可见、可编辑、必填和只读
发布运行时 → 按已发布表单元数据渲染运行端页面
视图/台账 → 通过新增、编辑、详情操作调用表单
Excel 导入导出 → 与字段规则、必填规则、默认值逻辑保持一致
审计日志 → 记录表单配置和运行端数据提交行为
```

P0 阶段表单设计器优先解决：

```text
1. 业务人员无需代码配置表单。
2. 表单组件必须绑定业务对象字段。
3. 表单支持主表、子表、附件、人员、部门、关联对象等常见企业应用场景。
4. 表单支持基础校验、显隐、只读、默认值和移动端自适应。
5. 表单可用于新增、编辑、查看、审批和流程发起。
6. 设计态修改不直接影响已发布运行态。
```

## 3. 目标用户

| 用户角色 | 使用目标 |
|---|---|
| 实施/配置顾问 | 为客户快速配置合同、报销、采购等业务表单，并适配流程和权限要求。 |
| 业务管理员 | 根据部门业务需要调整表单字段、布局、校验、显隐和只读规则。 |
| IT 管理员 | 审核表单配置是否符合权限、安全、发布和审计要求。 |
| 普通业务用户 | 在运行端填写、编辑、查看业务表单。 |
| 审批人/流程处理人 | 在审批节点查看业务数据、填写审批意见，并按节点权限编辑指定字段。 |
| 开发者 | 基于表单元数据实现运行时渲染、数据提交、校验、权限控制和扩展点。 |
| AI 开发助手 | 根据本文档生成表单 DSL、前端组件、后端接口、测试用例和开发任务。 |

## 4. 业务目标

P0 表单设计器需要满足以下业务目标：

| 目标 | 说明 |
|---|---|
| 可视化搭建 | 通过拖拽字段和配置属性完成表单搭建。 |
| 字段驱动 | 表单组件必须绑定数据对象字段，保障表单与数据模型一致。 |
| 支撑样板应用 | 能完整支撑合同申请、费用报销、采购申请三个样板应用表单。 |
| 支撑主子表 | 能配置报销明细、采购明细、付款计划等明细子表。 |
| 支撑流程 | 表单可作为流程发起表单、审批表单和归档查看表单。 |
| 支撑权限 | 表单字段可按角色、状态、流程节点配置可见、只读、必填。 |
| 支撑多端 | 表单在 PC 和移动端 H5 中可正常展示和提交。 |
| 支撑发布 | 草稿表单修改不影响已发布表单；发布后运行时读取已发布版本。 |
| 支撑审计 | 表单配置变更、发布、数据提交和关键操作均可追踪。 |
| 支撑扩展 | 后续可扩展自定义组件、脚本事件、复杂联动、表单模板市场等能力。 |

## 5A. P0 必做清单详表（执行版）

文档版本：v1.2  
更新日期：2026-05-06  
适用范围：`05-P0-form-designer.md`  

本章节用于把表单设计器从“拖拽组件”细化为可研发、可测试、可由 AI 后续生成设计器页面、运行时渲染器、表单 DSL、API、数据库表和测试用例的 P0 执行清单。表单设计器借鉴泛微 e-Builder 的“表单设计器 + 表单设置与管理”结构，但 P0 聚焦结构化布局、字段绑定、基础规则和多模式运行。


### 5A.1 P0 功能点描述统一要求

每一个 P0 功能点都必须具备可研发和可测试的描述，不得只写功能名称。后续 AI 生成页面、接口、数据库、任务拆解和测试用例时，应优先引用本章节中的功能编号。

| 描述项 | 要求 |
|---|---|
| 功能编号 | 使用 `P0-模块缩写-序号`，序号三位递增。 |
| 所属分类 | 标明业务分类，便于研发分包。 |
| 用户角色 | 标明主要操作者和受影响角色。 |
| 业务目标 | 说明该功能解决什么业务问题。 |
| 前置条件 | 说明执行前必须满足的状态、权限和数据。 |
| 输入内容 | 说明页面或接口需要输入的字段。 |
| 处理逻辑 | 说明前端、后端、运行时的关键处理规则。 |
| 输出结果 | 说明功能完成后产生的数据、状态或页面变化。 |
| 权限要求 | 说明需要校验的权限动作。 |
| 审计要求 | 说明是否写审计日志以及日志内容。 |
| 异常处理 | 说明失败场景和用户提示。 |
| 验收标准 | 说明测试如何确认功能完成。 |

### 5A.2 P0 功能优先级规则

| 优先级 | 含义 | 处理原则 |
|---|---|---|
| P0-Must | 主业务闭环必须依赖。 | 必须随 P0 首版交付。 |
| P0-Should | 对交付体验重要，但可在资源极限时降级。 | 原则纳入 P0，降级时保留入口和约束。 |
| P0-Guardrail | 安全、审计、发布稳定性相关。 | 必须纳入 P0，不可后补。 |

## 7. 核心概念定义

### 7.1 表单 Form

表单是面向用户的数据录入、编辑、查看和审批界面配置。

表单必须归属于某个应用，并绑定一个业务对象。

```text
应用 App
└── 业务对象 Object
    └── 表单 Form
        ├── 布局 Layout
        ├── 组件 Components
        ├── 字段绑定 Field Bindings
        ├── 表单规则 Rules
        └── 权限策略 Permissions
```

### 7.2 表单组件 Component

表单组件是画布中的最小展示和交互单元，包括字段组件和布局组件。

组件分为：

```text
字段组件：绑定业务对象字段，产生或展示业务数据
布局组件：组织页面结构，不直接产生业务数据
辅助组件：展示说明、分隔线、提示文本等
```

### 7.3 字段绑定 Field Binding

字段绑定是表单组件和业务对象字段之间的关系。

P0 原则：

```text
一个字段在同一个表单内默认只能绑定一次。
同一字段可在不同表单中重复使用。
系统字段可展示但不可编辑。
子表字段必须在子表组件内部使用。
附件字段必须使用附件/图片组件承载。
```

### 7.4 表单模式 Form Mode

同一个表单配置可在不同模式下运行：

| 模式 | 说明 |
|---|---|
| 新增模式 create | 用于创建新业务记录。 |
| 编辑模式 edit | 用于修改已有业务记录。 |
| 查看模式 view | 用于只读查看业务记录。 |
| 审批模式 approve | 用于流程节点处理，按节点字段权限控制。 |

### 7.5 表单规则 Form Rule

表单规则用于控制字段的可见、可编辑、必填、默认值和校验。

P0 支持以下规则类型：

```text
显隐规则
只读规则
必填规则
默认值规则
基础校验规则
```

## 12. 字段规则需求

### 12.1 必填规则

支持配置字段是否必填。

规则来源：

```text
对象字段必填规则
表单组件必填规则
流程节点必填规则
```

优先级建议：

```text
流程节点规则 > 表单规则 > 对象字段规则
```

业务规则：

```text
1. 新增和编辑模式提交时执行必填校验。
2. 查看模式不执行必填校验。
3. 审批模式按当前节点字段权限执行必填校验。
4. 隐藏字段原则上不触发前端必填校验，但后端需根据规则判断是否允许提交。
```

### 12.2 只读规则

只读规则用于控制字段是否可编辑。

支持条件：

```text
表单模式 = 查看/审批/编辑
业务状态 = 草稿/审批中/已通过/已驳回/已作废
用户角色 = 指定角色
流程节点 = 指定节点
字段值 = 指定值
```

业务规则：

```text
1. 系统字段默认只读。
2. 自动编号字段默认只读。
3. 流程审批中非授权字段默认只读。
4. 前端只读不可信，后端必须校验字段编辑权限。
```

### 12.3 显隐规则

显隐规则用于控制字段或布局区域是否展示。

P0 支持基础条件：

```text
字段等于
字段不等于
字段为空
字段不为空
金额大于
金额小于
状态等于
用户角色包含
流程节点等于
```

业务规则：

```text
1. 隐藏字段不应在前端展示。
2. 隐藏字段是否提交由后端规则决定，默认不允许前端修改隐藏字段。
3. 显隐规则循环依赖需要检测并阻止。
4. 多条件 P0 可支持 AND 组合；OR 组合可后续增强。
```

### 12.4 默认值规则

P0 支持默认值来源：

```text
固定值
当前用户
当前部门
当前时间
对象字段默认值
```

业务规则：

```text
1. 默认值在新增模式初始化时生效。
2. 编辑模式不应覆盖已有值。
3. 审批模式默认值只对节点新增可编辑字段生效。
4. 默认值必须经过字段类型校验。
```

### 12.5 校验规则

校验规则分为对象字段级和表单组件级。

P0 支持：

```text
必填
唯一
最小值/最大值
日期范围
文本长度
内置格式：手机号、邮箱、URL 可选
简单正则
附件数量限制
附件大小限制
```

校验要求：

```text
1. 前端提供即时校验和提交校验。
2. 后端提供权威校验。
3. 校验失败需返回字段级错误信息。
4. 子表校验需定位到具体行和字段。
```

### 13.4 子表业务规则

```text
3. 子表行删除应按业务数据规则处理，P0 可采用软删除标记。
4. 子表字段权限需要跟随主表权限和流程节点权限。
5. 子表校验失败时，主表不得提交成功。
```

## 15. 表单模式与运行规则

### 15.1 新增模式

新增模式用于创建业务记录。

规则：

```text
1. 初始化默认值。
2. 可编辑字段按表单和权限规则计算。
3. 提交后创建业务记录。
4. 如果绑定流程，提交后发起流程实例。
5. 提交成功后进入详情页、流程页或列表页，由配置决定。
```

### 15.2 编辑模式

编辑模式用于修改已有业务记录。

规则：

```text
1. 加载已有记录数据。
2. 按数据权限判断是否可编辑。
3. 按字段权限判断字段是否可编辑。
4. 已进入审批中的记录，P0 默认不允许普通编辑，需通过流程节点编辑。
5. 提交时记录变更日志。
```

### 15.3 查看模式

查看模式用于只读展示记录。

规则：

```text
1. 所有字段默认只读。
2. 不展示提交按钮。
3. 可展示附件、流程日志、操作记录。
4. 按字段可见权限过滤内容。
```

### 15.4 审批模式

审批模式用于流程节点处理。

规则：

```text
1. 根据当前任务和节点权限加载表单。
2. 只有当前处理人可进入可处理状态。
3. 可编辑字段由流程节点字段权限决定。
4. 审批意见由流程引擎记录。
5. 通过、驳回等按钮由流程引擎提供。
6. 审批提交时同时校验表单字段和流程操作权限。
```

```text

```

## 17. 状态流转

### 17.1 表单状态

```text
草稿 → 已发布 → 已修改未发布 → 已停用 → 已删除
   ↑        ↓             ↓
   └────── 回滚 ←─────────┘
```

状态说明：

| 状态 | 说明 |
|---|---|
| 草稿 | 表单正在设计，未对运行端生效。 |
| 已发布 | 表单已随应用或单独发布到运行态。 |
| 已修改未发布 | 表单发布后又发生草稿修改，但运行端仍使用旧版本。 |
| 已停用 | 表单不可被新增引用，但历史运行数据仍可查看。 |
| 已删除 | 表单进入回收站。 |

### 17.2 表单运行状态

运行端表单根据业务记录和流程状态进入不同模式：

```text
无记录 → 新增模式
已有记录 + 可编辑 → 编辑模式
已有记录 + 只读 → 查看模式
流程任务处理中 → 审批模式
流程结束 → 查看模式
记录作废 → 查看模式，只允许授权恢复或查看
```

## 18. 业务规则

### 18.1 字段与组件一致性

```text
1. 字段组件类型必须与字段类型匹配。
2. 字段被删除或停用后，表单需要提示异常引用。
3. 对象字段改名后，表单显示名称可选择同步或保持自定义标签。
4. 字段编码变更需谨慎，P0 建议不允许已发布字段变更编码。
```

### 18.2 表单提交规则

```text
1. 表单提交必须携带表单版本号。
2. 后端按发布版本解析提交数据。
3. 提交字段必须属于表单允许提交字段。
4. 隐藏或只读字段默认不允许被前端修改。
5. 服务端校验失败时不得创建或更新业务数据。
6. 子表提交需保持主从数据一致性。
```

### 18.3 设计态与运行态隔离

```text
1. 设计态保存草稿不影响运行态。
2. 发布后生成不可变表单版本快照。
3. 运行态始终读取已发布版本。
4. 历史流程实例应继续使用发起时对应的表单版本。
```

### 18.4 移动端适配规则

```text
1. PC 两栏布局在移动端自动转为单列。
2. 子表在移动端优先使用卡片式行编辑。
3. 附件上传需适配移动端选择文件/图片。
4. 操作按钮需固定在底部或明显位置。
5. 移动端不要求与 PC 完全一致，但字段和权限必须一致。
```

## 19. 异常处理

| 异常场景 | 处理要求 |
|---|---|
| 表单引用已删除字段 | 设计器提示错误，禁止发布。 |
| 字段类型与组件不匹配 | 设计器提示错误，禁止保存或禁止发布，具体由产品策略决定。 |
| 必填字段未放入表单 | 发布前提示风险；如果对象级必填则应禁止发布。 |
| 用户无记录权限 | 运行端提示无权限，不返回敏感字段。 |
| 用户提交只读字段变更 | 后端拒绝，并记录安全日志。 |
| 子表校验失败 | 返回具体行号和字段错误。 |
| 附件上传失败 | 展示失败原因，允许重试。 |
| 表单版本过期 | 提示刷新后重试，避免用旧版本提交。 |
| 流程任务已被处理 | 提示任务状态已变化，不允许重复提交。 |
| 网络中断 | 前端提示保存失败；P0 不要求离线暂存。 |

P0 存储原则：

```text
5. 删除采用软删除。
```

## 27. 验收标准

### 27.1 模块级验收

```text
1. 搭建者可基于任意已发布对象创建表单。
2. 搭建者可从字段列表拖拽字段到画布，并配置基础属性。
3. 表单支持单列、两栏、分组、说明文本等基础布局。
4. 表单支持文本、数字、金额、日期、单选、多选、人员、部门、附件、图片、关联对象和子表组件。
5. 表单支持必填、只读、显隐、默认值和基础校验。
6. 表单支持 PC 和移动端 H5 预览。
7. 表单保存草稿不影响已发布运行态。
8. 表单发布后运行端按版本渲染。
9. 表单提交时前后端均执行校验。
10. 无权限用户不可查看或修改未授权字段。
11. 子表可新增、编辑、删除明细行，并在校验失败时提示到具体行字段。
12. 附件字段可上传、下载、删除，并受字段权限控制。
13. 表单配置变更和运行端提交行为可审计。
```

### 27.2 样板应用验收

```text
1. 可创建合同申请表单，并支持合同附件上传和合同金额校验。
2. 可创建费用报销表单，并支持费用明细子表和金额合计展示。
3. 可创建采购申请表单，并支持采购明细子表、供应商关联和预算金额字段。
4. 三个样板表单均可作为流程发起表单。
5. 审批节点可按节点权限控制字段只读和可编辑。
6. 三个样板表单均可在移动端 H5 正常填写和提交。
```

## 29. 给 AI 生成代码/设计的提示

后续 AI 基于本文档生成内容时，必须遵守以下约束：

```text
1. 不要把表单写死成固定业务页面，必须按表单元数据动态渲染。
2. 表单组件必须绑定对象字段，不允许脱离数据模型独立存储业务字段。
3. 所有设计态配置都要保存为可序列化 JSON/DSL。
4. 运行态必须读取已发布版本，不读取草稿版本。
5. 所有 API 必须包含租户、应用、权限和版本上下文。
6. 前端只读和隐藏不可信，后端必须做字段级权限校验。
7. 删除表单、字段、组件都要考虑依赖检查和软删除。
8. 不要实现 P0 不做范围中的在线 IDE、插件市场、任意脚本、复杂公式和原生 App。
9. 优先保证合同、费用报销、采购申请三个样板应用表单可运行。
10. 表单 DSL、对象 DSL、流程 DSL、权限 DSL 的字段编码必须保持一致。
11. 代码生成时应区分设计器端和运行时端。
12. 测试用例必须覆盖 PC、移动端、权限、子表、附件、流程审批模式和异常提交。
```
