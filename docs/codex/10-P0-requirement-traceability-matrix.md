# 10-P0-requirement-traceability-matrix.md

## 1. 文档目的

本文档用于将 P0 第一批平台主干需求文档中的功能点统一汇总为 **需求追踪矩阵（Requirement Traceability Matrix, RTM）**。

它的核心作用是：

```text
1. 锁定 P0 需求基线，避免后续范围漂移。
2. 建立功能点与数据库、API、前端、权限、审计、测试验收之间的映射。
3. 明确每个功能点的主责模块、依赖模块和后续设计产物。
4. 为后续生成系统架构、数据库设计、API 设计、页面组件设计、任务拆解和测试用例提供统一索引。
```

本文档不是替代各模块需求文档，而是作为后续设计、研发、测试和 AI 生成工作的总索引。

## 4. 优先级定义

| 优先级 | 含义 | 处理要求 |
|---|---|---|
| `P0-Must` | 主业务闭环必须依赖 | 必须随 P0 首版交付 |
| `P0-Should` | 对交付体验重要，但可在极端资源不足时降级 | 原则纳入 P0；降级时必须保留入口、数据结构或扩展点 |
| `P0-Guardrail` | 安全、审计、权限、发布稳定性、运行稳定性相关 | 必须纳入 P0，不可后补 |

## 6. 跨模块依赖矩阵

| 主责模块 | 依赖模块 | 依赖说明 |
|---|---|---|
| 应用中心 | 组织用户角色、权限系统、发布运行时 | 应用可见范围、成员授权、设计入口、发布入口和运行入口依赖这些模块。 |

| 数据对象建模 | 应用中心、权限系统、发布运行时 | 对象必须归属应用，字段操作需权限控制，发布后生成运行时元数据。 |
| 表单设计器 | 数据对象建模、组织用户角色、权限系统、发布运行时 | 表单组件绑定字段，人员/部门组件读取组织，运行态需权限和发布快照。 |

| 权限系统 | 全部主干模块 | 权限是跨模块能力，控制设计态、运行态、字段、数据、流程、发布和审计访问。 |
| 发布、版本与运行时 | 应用中心、数据建模、表单、流程、权限 | 发布运行时负责把设计态元数据打包成快照，并驱动运行态渲染和执行。 |

## 11. 范围控制规则

后续设计和开发必须遵守以下规则：

```text
1. 不得在 P0 设计中引入未在本矩阵或基线文档中出现的复杂能力。
2. 如需新增 P0 功能点，必须先新增编号并更新本矩阵。
3. P1/P2/P3 能力可以作为扩展点写入，但不得影响 P0 交付范围。
4. 所有关键操作必须关联权限要求和审计要求。
5. 所有运行态能力必须经过统一权限校验。
6. 所有设计态修改不得直接影响已发布运行态版本。
7. 所有配置产物必须可序列化为 JSON 元数据。
8. 删除类操作默认软删除，物理删除不作为 P0 默认行为。
```
