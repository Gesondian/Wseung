# 02-P0-app-center.md

## 1. 文档目的

本文档用于定义 **企业级低代码平台 v1.2 P0 阶段的应用中心模块需求**。

应用中心是平台的一级入口，也是低代码应用的顶层容器管理模块。后续以下能力都必须挂载在某个应用之下：

```text
数据对象建模
表单设计器
视图/台账
流程审批
权限系统
发布与运行时
基础看板
Excel 导入导出
模板中心
审计日志
回收站
```

本文档面向产品、架构、前端、后端、测试、实施以及后续 AI 生成系统架构、数据库设计、API 文档、代码骨架和测试用例使用。

---

## 2. 模块定位

应用中心用于让平台管理员、实施顾问和业务管理员创建、管理、分类、授权、停用、删除、恢复和进入业务应用。

在低代码平台中，**应用 App** 是最高层级的业务容器。一个应用通常对应一类企业业务场景，例如：

```text
合同管理应用
费用报销应用
采购申请应用
资产管理应用
客户管理应用
```

一个应用内部可以包含：

```text
业务对象
字段
表单
视图
流程
页面
看板
权限
模板信息
发布版本
运行数据
审计日志
```

P0 阶段的应用中心目标是：

> **提供低代码应用从创建、配置、授权、发布入口、运行入口到停用、删除、恢复的基础管理能力，并支撑合同管理、费用报销、采购申请三个样板应用的创建和交付。**

应用中心不负责直接实现表单、流程、权限、运行时等具体业务逻辑，但必须提供这些模块的统一入口、归属关系和状态管理。

## 3. 目标用户

| 用户角色 | 使用目标 |
|---|---|
| 平台超级管理员 | 管理全平台应用范围、查看所有应用、处理异常应用和回收站。 |
| 租户/企业管理员 | 管理本企业应用，创建应用分类，配置应用负责人和授权范围。 |
| 实施/配置顾问 | 从空白或模板创建应用，进入设计器完成业务搭建和交付。 |
| 业务管理员 | 管理部门应用，调整应用名称、描述、入口、负责人和使用范围。 |
| 应用设计者 | 进入应用设计态，配置数据对象、表单、视图、流程和页面。 |
| 普通业务用户 | 在授权范围内看到可使用的应用，并进入运行端办理业务。 |
| 审计/运维人员 | 查看应用创建、发布、停用、删除、恢复、导入导出等日志。 |
| AI 开发助手 | 根据本文档生成应用中心页面、接口、数据模型、权限和测试用例。 |

## 4. 业务目标

P0 阶段应用中心需要满足以下业务目标：

| 目标 | 说明 |
|---|---|
| 统一应用入口 | 所有低代码业务应用必须在应用中心创建、展示和管理。 |
| 支撑快速创建 | 支持空白创建和从合同/报销/采购模板创建应用。 |
| 支撑分类管理 | 支持按文件夹/分类管理应用，便于企业多部门使用。 |
| 支撑设计入口 | 能从应用中心进入数据建模、表单、视图、流程、权限、发布等设计入口。 |
| 支撑运行入口 | 已发布且有权限的用户可从应用中心进入运行端。 |
| 支撑生命周期 | 支持应用创建、编辑、发布入口、停用、恢复、删除到回收站。 |
| 支撑基础迁移 | 支持应用元数据导入导出，为私有化交付和模板复用预留能力。 |
| 支撑权限隔离 | 不同角色看到和能操作的应用范围不同。 |
| 支撑审计追踪 | 应用关键操作必须可追踪。 |
| 支撑样板应用 | 能创建并管理合同管理、费用报销、采购申请三个样板应用。 |

## 5. P0 范围

P0 应用中心必须支持以下能力。

| 分类 | 功能点 | P0 要求 |
|---|---|---|
| 应用列表 | 应用卡片/列表展示 | 支持展示应用名称、图标、状态、负责人、创建人、更新时间、发布状态。 |
| 应用列表 | 搜索 | 支持按应用名称、编码、描述、负责人搜索。 |
| 应用列表 | 筛选 | 支持按应用状态、分类、创建人、我管理的、我使用的筛选。 |
| 应用列表 | 排序 | 支持按更新时间、创建时间、名称排序。 |
| 应用分类 | 文件夹/分类 | 支持创建、编辑、删除应用分类。 |
| 应用分类 | 应用移动分类 | 支持将应用移动到指定分类。 |
| 应用创建 | 空白创建 | 支持输入应用名称、编码、图标、描述、分类创建空白应用。 |
| 应用创建 | 模板创建 | 支持从合同管理、费用报销、采购申请模板创建应用。 |
| 应用编辑 | 基础信息编辑 | 支持修改应用名称、图标、描述、分类、负责人。 |
| 应用详情 | 应用概览 | 展示应用基础信息、状态、最近发布版本、资源数量、最近操作。 |
| 应用详情 | 设计入口 | 提供进入对象、表单、视图、流程、权限、发布等模块入口。 |
| 应用详情 | 运行入口 | 已发布应用可进入运行端预览或使用。 |
| 应用状态 | 停用应用 | 停用后普通用户不可进入运行端，设计和管理入口保留。 |
| 应用状态 | 恢复启用 | 停用应用可恢复启用。 |
| 删除恢复 | 软删除 | 删除应用进入回收站，不立即物理删除。 |
| 删除恢复 | 恢复应用 | 回收站中应用可恢复到删除前状态。 |
| 导入导出 | 导出应用元数据包 | 支持导出应用配置元数据，P0 默认不导出业务数据。 |
| 导入导出 | 导入应用元数据包 | 支持导入合法应用包，并做应用编码冲突检测。 |
| 权限入口 | 应用成员管理入口 | 支持查看/维护应用管理员、设计者、使用者、只读者。 |
| 审计日志 | 应用操作日志 | 创建、编辑、停用、恢复、删除、导入、导出、模板安装均写审计。 |

## 5A. P0 必做清单详表（执行版）

文档版本：v1.2  
更新日期：2026-05-06  
适用范围：`02-P0-app-center.md`  

本章节用于把应用中心从“应用列表与入口”细化为可研发、可测试、可由 AI 后续生成页面、API、数据库、权限和测试用例的 P0 执行清单。应用中心借鉴泛微 e-Builder 的“应用作为顶层业务容器”思路，但 P0 只实现应用资产与生命周期管理的最小闭环。


### 5A.1 P0 功能点描述统一要求

每一个 P0 功能点都必须具备可研发和可测试的描述，不得只写功能名称。后续 AI 生成页面、接口、数据库、任务拆解和测试用例时，应优先引用本章节中的功能编号。

| 描述项 | 要求 |
|---|---|
| 功能编号 | 使用 `P0-模块缩写-序号`，序号三位递增。 |
| 所属分类 | 标明业务分类，便于研发分包。 |
| 用户角色 | 标明主要操作者和受影响角色。 |
| 业务目标 | 说明该功能解决什么业务问题。 |
| 前置条件 | 说明执行前必须满足的状态、权限和数据。 |
| 输入内容 | 说明页面或接口需要输入的字段。 |
| 处理逻辑 | 说明前端、后端、运行时的关键处理规则。 |
| 输出结果 | 说明功能完成后产生的数据、状态或页面变化。 |
| 权限要求 | 说明需要校验的权限动作。 |
| 审计要求 | 说明是否写审计日志以及日志内容。 |
| 异常处理 | 说明失败场景和用户提示。 |
| 验收标准 | 说明测试如何确认功能完成。 |

### 5A.2 P0 功能优先级规则

| 优先级 | 含义 | 处理原则 |
|---|---|---|
| P0-Must | 主业务闭环必须依赖。 | 必须随 P0 首版交付。 |
| P0-Should | 对交付体验重要，但可在资源极限时降级。 | 原则纳入 P0，降级时保留入口和约束。 |
| P0-Guardrail | 安全、审计、发布稳定性相关。 | 必须纳入 P0，不可后补。 |

### 5A.4 P0 应用中心必做功能明细

#### P0-AC-001 应用中心首页

| 描述项 | 内容 |
|---|---|
| 所属分类 | AC-C01 |
| 用户角色 | 企业管理员、应用管理员、应用设计者、普通业务用户 |
| 业务目标 | 提供统一应用入口，让不同角色看到自己可管理或可使用的应用。 |
| 前置条件 | 用户已登录，tenantId 可解析。 |
| 输入内容 | 无必填；可输入搜索、筛选和排序条件。 |
| 处理逻辑 | 根据用户权限加载应用；管理员可见管理范围内应用，普通用户仅见可访问应用。 |
| 输出结果 | 应用卡片/列表、分类栏、创建入口、搜索筛选区。 |
| 权限要求 | `app.view`；创建入口需 `app.create`。 |
| 审计要求 | 普通访问不审计；导出、删除、停用等操作审计。 |
| 异常处理 | 无应用时展示空状态和创建/模板引导；无权限时展示空列表。 |
| 验收标准 | 普通用户登录后只看到被授权的合同、报销、采购等应用。 |

#### P0-AC-005 应用分类/文件夹管理

| 描述项 | 内容 |
|---|---|
| 所属分类 | AC-C02 |
| 用户角色 | 企业管理员、应用管理员 |
| 业务目标 | 按部门、业务域或交付项目组织应用。 |
| 前置条件 | 当前用户具备分类管理权限。 |

#### P0-AC-009 Excel 创建应用入口

| 描述项 | 内容 |
|---|---|
| 所属分类 | AC-C03 |
| 用户角色 | 应用管理员、实施顾问 |
| 业务目标 | 从 Excel 表头快速生成对象、字段、默认表单和视图。 |
| 前置条件 | 用户具备应用创建权限；Excel 文件符合大小和格式限制。 |
| 输入内容 | Excel 文件、应用名称、对象名称、是否生成默认表单/视图。 |
| 处理逻辑 | P0 可实现基础解析；复杂多表关系后置。解析结果需人工确认后创建。 |
| 输出结果 | 应用、对象、字段、默认表单、默认视图草稿。 |
| 权限要求 | `app.create`、`excel.import`。 |
| 审计要求 | 记录 Excel 创建应用行为，不记录敏感明细到审计。 |
| 异常处理 | 文件格式错误、表头为空、字段类型无法识别时提示修正。 |
| 验收标准 | 上传简单台账 Excel 后可生成一个数据采集应用草稿。 |

### 5A.5 P0 应用中心完成定义 Definition of Done

```text
1. 用户可按权限看到可管理或可使用的应用。
2. 支持应用卡片/列表、搜索、筛选、排序和分类管理。
3. 支持空白创建、模板创建、Excel 创建入口。
4. 应用详情页提供对象、表单、视图、流程、权限、发布、运行、日志入口。
5. 应用可停用、恢复、软删除、从回收站恢复。
6. 应用成员管理入口可维护管理员、设计者、使用者、只读者。
7. 应用元数据可导出和导入，P0 默认不包含业务数据。
8. 创建、编辑、停用、恢复、删除、导入、导出、模板安装必须审计。
9. 合同、费用报销、采购申请三个样板应用可以从模板创建。
10. 应用中心不实现具体引擎逻辑，只负责资源组织、入口和生命周期。
```

## 6. P0 不做范围

以下能力不进入 P0，需在 PRD 和后续 AI 生成中明确排除：

| 能力 | 处理方式 |
|---|---|
| 完整应用市场/云商店 | P0 不做；只提供内置模板创建能力。 |
| ISV 上架、审核、售卖、计费 | P3。 |
| 复杂应用复制策略 | P0 可通过模板创建或导入导出间接实现；完整复制放 P1/P2。 |
| 应用灰度发布 | P2；P0 只做发布入口和版本管理依赖。 |
| 多环境 Dev/Test/Prod 发布流水线 | P2；P0 仅区分设计态、发布态、运行态。 |
| 应用依赖拓扑可视化 | P2。 |
| 应用访问量高级分析 | P2；P0 只保留基础运行入口和操作日志。 |

## 7. 核心概念定义

### 7.1 应用 App

应用是低代码平台的顶层业务容器。

```text
一个应用可以包含多个业务对象、表单、视图、流程、页面、看板和权限配置。
一个业务对象、表单或流程必须归属到某个应用。
```

应用至少包含：

```text
应用名称
应用编码
应用图标
应用描述
应用分类
应用负责人
应用状态
发布状态
当前发布版本
创建人
创建时间
更新时间
所属租户
```

### 7.2 应用编码 App Key

应用编码是应用在租户内的唯一标识。

要求：

```text
同一租户内应用编码唯一
创建后原则上不允许随意修改
导入应用包时必须做编码冲突检测
后续 API、元数据包、模板安装均依赖应用编码
```

示例：

```text
contract_management
expense_reimbursement
procurement_request
```

### 7.3 应用分类 App Folder / Category

应用分类用于按部门、业务线、用途组织应用。

P0 支持一级分类即可。

示例：

```text
行政人事
财务管理
采购供应链
销售客户
项目管理
```

P1/P2 可扩展多级分类、标签和应用收藏。

### 7.4 应用状态 App Status

P0 应用状态建议包括：

```text
DRAFT：草稿/未发布
PUBLISHED：已发布/运行中
STOPPED：已停用
RECYCLED：已删除进入回收站
```

临时任务状态可包括：

```text
CREATING：创建中
IMPORTING：导入中
EXPORTING：导出中
TEMPLATE_INSTALLING：模板安装中
```

临时状态不应作为长期业务状态保留，只用于任务进度提示。

### 7.5 发布状态 Release Status

应用状态和发布版本相关，但不是同一概念。

```text
应用状态：应用是否可管理、可运行、已停用、已删除
发布状态：应用是否存在已发布版本、当前运行哪个版本
```

例如：

```text
应用可以处于 PUBLISHED 状态，并运行 v3 版本。
应用也可以处于 DRAFT 状态，表示尚未发布。
应用停用后仍然保留历史发布版本。
```

发布、回滚和运行时细节以 `09-P0-release-runtime.md` 为准。

### 7.6 应用成员 App Member

应用成员用于描述用户或角色在某个应用中的职责。

P0 建议内置：

```text
应用所有者 App Owner
应用管理员 App Admin
应用设计者 App Designer
应用使用者 App User
应用只读者 App Viewer
```

具体权限由 `08-P0-permission-system.md` 统一解释。

### 7.7 应用模板 App Template

应用模板是预置的一组元数据包，用于快速创建应用。

P0 仅内置三个模板：

```text
合同管理模板
费用报销模板
采购申请模板
```

模板安装后会生成独立应用副本。模板本身与应用副本解耦，修改应用不反向影响模板。

## 8. 核心用户故事

### 8.1 从空白创建应用

作为实施顾问，我希望可以创建一个空白应用，填写应用名称、编码、分类和负责人，然后进入设计器配置数据对象、表单、流程和权限。

验收：

```text
应用创建后出现在应用列表中。
应用状态为 DRAFT。
应用创建人自动成为应用所有者。
系统自动生成默认菜单和设计入口。
```

### 8.2 从模板创建应用

作为实施顾问，我希望可以从合同管理、费用报销、采购申请模板创建应用，减少重复搭建成本。

验收：

```text
用户选择模板后可填写新应用名称和编码。
系统复制模板元数据到新应用。
新应用进入 DRAFT 状态。
用户可继续修改对象、表单、流程和权限。
```

### 8.3 管理应用分类

作为企业管理员，我希望可以将不同业务应用放入不同分类，方便部门用户查找。

验收：

```text
管理员可以创建分类。
应用可以移动到分类下。
删除分类前需要处理分类下已有应用。
```

### 8.4 停用应用

作为应用管理员，我希望可以停用暂时不再使用的应用，避免普通用户继续提交数据。

验收：

```text
应用停用后普通用户无法进入运行端。
管理员仍可进入管理和设计入口。
历史数据不被删除。
停用操作写入审计日志。
```

### 8.5 删除并恢复应用

作为应用管理员，我希望误删应用后可以从回收站恢复，避免配置和业务数据丢失。

验收：

```text
删除应用进入回收站。
回收站内应用不在普通应用列表展示。
有权限用户可以恢复应用。
恢复后保留删除前配置、发布版本和数据。
```

### 8.6 导入导出应用元数据包

作为实施顾问，我希望可以导出一个应用的配置元数据，并导入到另一个环境，支持私有化交付和复用。

验收：

```text
导出的应用包包含应用、对象、字段、表单、视图、流程、权限、模板相关元数据。
导入时检测应用编码冲突。
导入失败时不产生半成品应用。
```

```text
数据对象

视图/台账
流程设计
权限配置
基础看板
发布管理
```

进入规则：

```text
应用设计者、应用管理员、应用所有者可进入设计入口。
普通应用使用者不可进入设计入口。
只读者不可进入设计入口。
停用应用仍允许管理员进入设计入口。
回收站中的应用不允许进入设计入口，需先恢复。
```

### 9.9 运行入口

应用中心应为已发布应用提供运行入口。

进入规则：

```text
应用必须存在已发布版本。
应用状态必须为 PUBLISHED。
用户必须拥有应用使用或只读权限。
运行时仍需再次校验菜单、对象、数据和字段权限。
```

如果应用未发布，应提示：

```text
该应用尚未发布，请先完成发布后再访问运行端。
```

如果应用已停用，应提示：

```text
该应用已停用，暂不可访问。
```

### 9.10 应用停用与恢复启用

停用应用用于临时关闭应用运行入口。

停用影响：

```text
普通用户无法进入运行端。
新建数据和提交流程被阻止。
已打开页面再次提交时需提示应用已停用。
管理员仍可进入应用管理和设计入口。
应用数据、配置、发布版本不删除。
```

恢复启用影响：

```text
应用恢复到停用前发布版本。
有权限用户可重新进入运行端。
恢复操作写审计日志。
```

停用前提示：

```text
停用后用户将无法访问该应用运行端，未完成流程可能无法继续处理，确认停用？
```

### 9.11 应用删除与回收站

P0 删除应用必须采用软删除。

删除后影响：

```text
应用状态变为 RECYCLED。
普通应用列表不展示。
运行端不可访问。
设计入口不可访问。
配置、发布版本、业务数据保留。
可在回收站恢复。
```

删除前系统应提示：

```text
应用删除后将进入回收站，普通用户不可访问，相关待办可能无法继续处理。确认删除？
```

P0 不做彻底物理删除。彻底删除可由 `13-P0-audit-recycle-bin.md` 在后续版本定义。

### 9.12 应用恢复

恢复规则：

```text
只有具备应用恢复权限的管理员可恢复。
恢复后应用回到删除前状态。
如果删除前为 PUBLISHED，则恢复后仍为 PUBLISHED。
如果删除前为 STOPPED，则恢复后仍为 STOPPED。
如果应用分类已不存在，则恢复到未分类。
恢复后写审计日志。
```

异常处理：

```text
如果应用编码已被新应用占用，恢复失败，提示需先处理编码冲突。
如果恢复依赖资源缺失，恢复失败并提示缺失资源。
```

### 9.13 应用导出

P0 应用导出默认导出元数据包。

导出内容建议包括：

```text

fields.json
forms.json
views.json
workflows.json
permissions.json
dashboards.json
menus.json
version.json
manifest.json
```

P0 默认不导出：

```text

审批任务数据
审计日志
用户账号和组织架构
文件附件实体
```

导出前校验：

```text
应用存在
用户有导出权限
应用不在回收站
应用元数据完整
```

### 9.14 应用导入

P0 应用导入用于导入应用元数据包。

导入流程：

```text
上传应用包
解析 manifest
校验版本兼容性
校验应用编码冲突
校验元数据完整性
预览导入内容
确认导入
创建应用和相关元数据
写入导入日志
```

冲突处理策略：

```text
P0 默认不覆盖已有应用。
如应用编码冲突，要求用户输入新应用编码后导入。
如字段、对象、流程内部引用异常，导入失败并回滚。
```

P0 不做复杂合并导入、增量覆盖和跨版本自动迁移。

## 11. 状态流转

### 11.1 应用主状态

P0 应用状态流转如下：

```text
创建空白/模板安装
  ↓
DRAFT
  ↓ 发布成功
PUBLISHED
  ↓ 停用
STOPPED
  ↓ 恢复启用
PUBLISHED
  ↓ 删除
RECYCLED
  ↓ 恢复
删除前状态
```

### 11.2 状态流转表

| 当前状态 | 操作 | 目标状态 | 说明 |
|---|---|---|---|
| 无 | 创建空白应用 | DRAFT | 生成草稿应用。 |
| 无 | 从模板创建 | DRAFT | 复制模板元数据生成草稿应用。 |
| DRAFT | 发布成功 | PUBLISHED | 发布逻辑见发布运行时文档。 |
| PUBLISHED | 停用 | STOPPED | 关闭运行入口。 |
| STOPPED | 恢复启用 | PUBLISHED | 恢复运行入口。 |
| DRAFT | 删除 | RECYCLED | 未发布应用进入回收站。 |
| PUBLISHED | 删除 | RECYCLED | 已发布应用进入回收站，运行入口关闭。 |
| STOPPED | 删除 | RECYCLED | 停用应用进入回收站。 |
| RECYCLED | 恢复 | 删除前状态 | 恢复到删除前状态。 |

### 11.3 不允许的状态操作

| 状态 | 不允许操作 | 说明 |
|---|---|---|
| RECYCLED | 设计、发布、运行 | 必须先恢复。 |
| STOPPED | 普通用户运行 | 停用状态禁止运行端访问。 |
| DRAFT | 普通用户运行 | 未发布无运行版本。 |
| IMPORTING | 删除、发布 | 导入任务未完成前禁止关键操作。 |
| EXPORTING | 删除 | 导出中禁止删除，避免包不一致。 |

## 13. 业务规则

### 13.1 应用编码唯一

同一租户下，应用编码必须唯一。

```text
tenant_id + app_key 唯一
```

### 13.2 创建人默认成为应用所有者

应用创建成功后：

```text
创建人自动成为 App Owner。
App Owner 默认拥有当前应用全部权限。
```

### 13.3 应用删除必须软删除

P0 不允许应用直接物理删除。

```text
删除仅标记 deleted_at 和 status = RECYCLED。
```

### 13.4 应用停用不删除数据

应用停用仅影响运行访问。

```text
配置保留
数据保留
发布版本保留
审计保留
管理员管理入口保留
```

### 13.5 设计态与运行态隔离

应用中心必须遵循设计态和运行态隔离原则。

```text
草稿配置修改不影响已发布运行版本。
运行端只读取已发布版本元数据。
```

### 13.6 模板创建生成独立副本

从模板创建应用后：

```text
新应用拥有独立元数据。
模板后续修改不影响已创建应用。
应用修改也不影响模板。
```

### 13.7 导入失败必须回滚

导入过程中任意关键资源创建失败，应回滚本次导入。

```text
不能产生只有 app 记录但缺少对象、表单、流程等元数据的半成品应用。
```

### 13.8 回收站恢复需校验冲突

恢复应用前必须校验：

```text
应用编码未被占用
必要依赖元数据仍存在
用户有恢复权限
```

## 14. 异常处理

| 场景 | 处理方式 |
|---|---|
| 应用编码重复 | 阻止创建或导入，提示修改编码。 |
| 应用名称为空 | 阻止提交，提示必填。 |
| 应用编码格式非法 | 阻止提交，提示仅允许小写字母、数字、下划线等规则。 |
| 模板安装失败 | 回滚创建事务，记录错误日志。 |
| 应用包格式非法 | 阻止导入，提示应用包不合法。 |
| 应用包版本不兼容 | 阻止导入或提示不支持当前版本。 |
| 导入过程中资源引用缺失 | 导入失败并回滚。 |
| 用户无权限访问应用 | 返回无权限提示，不展示敏感应用信息。 |
| 停用应用被普通用户访问 | 提示应用已停用。 |
| 回收站应用被访问 | 提示应用不存在或已删除。 |
| 删除应用存在未完成流程 | P0 可允许删除但必须强提示；恢复后可继续访问。 |
| 恢复应用编码冲突 | 阻止恢复，提示管理员处理冲突。 |

```json
      "name": "合同管理",

  "icon": "contract",
```

## 21. 验收标准

### 21.1 应用创建验收

- 管理员或有权限用户可以创建空白应用。
- 创建应用时应用编码重复会被拦截。
- 创建人自动成为应用所有者。
- 新应用默认状态为 DRAFT。
- 创建操作写入审计日志。

### 21.2 模板创建验收

- 用户可以从合同管理模板创建应用。
- 用户可以从费用报销模板创建应用。
- 用户可以从采购申请模板创建应用。
- 模板创建后应用内包含对象、表单、视图、流程和权限建议。
- 模板创建失败时不产生半成品应用。

### 21.3 应用列表验收

- 普通用户只看到自己有权限访问的应用。
- 应用管理员可看到自己管理的应用。
- 租户管理员可看到本租户全部应用。
- 支持名称搜索、状态筛选、分类筛选和排序。

### 21.4 应用分类验收

- 管理员可以创建应用分类。
- 应用可以移动到指定分类。
- 分类下存在应用时不允许删除分类。

### 21.5 应用详情验收

- 应用详情页可以查看基础信息、状态、当前版本和资源统计。
- 有设计权限的用户可以进入设计入口。
- 有运行权限且应用已发布的用户可以进入运行端。
- 无权限用户无法进入详情或运行端。

### 21.6 应用停用验收

- 已发布应用可以被停用。
- 停用后普通用户无法进入运行端。
- 停用后管理员仍可进入管理入口。
- 停用不删除配置、数据和发布版本。
- 停用操作写入审计日志。

### 21.7 删除恢复验收

- 应用删除后进入回收站。
- 回收站应用不在普通应用列表展示。
- 回收站应用不可运行、不可设计、不可发布。
- 有权限用户可以恢复应用。
- 恢复后应用回到删除前状态。
- 删除和恢复均写入审计日志。

### 21.8 导入导出验收

- 有权限用户可以导出应用元数据包。
- 导出包包含 manifest 和核心元数据文件。
- 导入时能检测应用编码冲突。
- 导入失败时事务回滚。
- 导入导出操作写审计日志。

### 21.9 跨模块验收

- 从应用中心进入数据建模模块时，能带入正确 app_id。
- 从应用中心进入表单设计器时，能加载当前应用对象。
- 从应用中心进入流程设计器时，流程归属当前应用。
- 从应用中心进入权限配置时，只配置当前应用权限。
- 从应用中心进入发布管理时，发布当前应用草稿配置。

## 23. 给 AI 生成代码/设计的提示

后续 AI 基于本文档生成架构、代码、接口或测试用例时，必须遵守以下约束：

```text
1. 不要把表单、流程、权限逻辑写死在应用中心模块中。
2. 应用中心只负责应用容器、状态、分类、成员、入口和导入导出管理。
3. 所有应用数据必须带 tenant_id。
4. 同一租户下 app_key 必须唯一。

10. 模板创建生成独立应用副本，不能与模板共享可变元数据。
11. 应用中心必须写审计日志。
12. P0 不做应用市场、插件市场、AI 自动建应用、灰度发布和多环境流水线。
13. 应用发布、版本和回滚逻辑以 09-P0-release-runtime.md 为准。
```
