## 1. 本批目标

本批只设计应用中心首页最基础的浏览与定位能力：

```text
P0-AC-001 应用中心首页
P0-AC-002 应用卡片/列表展示
P0-AC-003 应用搜索
P0-AC-004 应用筛选与排序
```

本批不设计：

```text
1. 分类创建、编辑、删除。
2. 应用移动分类。
3. 创建空白应用、模板创建、Excel 创建。
4. 应用详情页。
5. 发布、停用、恢复、删除、回收站。
6. 成员管理、导入导出、操作日志。
```

这些能力进入后续小批次。

## 4. 页面信息架构

应用中心首页借鉴 e-Builder 类后台工作台的信息密度，但只保留 P0 范围内的能力。参考图中的数据加工、动作流、规则引擎、集成、开发、运维、回收站、新建应用、新建文件夹、第三方标签、资源数量等能力不属于本批 `P0-AC-001 ~ P0-AC-004`，不进入本批设计。

本批采用“全局框架 + 筛选导航 + 应用展示”的后台工作台布局：

```text
全局框架
  - 顶部栏：平台标识、当前用户、全局搜索入口预留
  - 左侧模块导航：仅高亮“应用中心”，其他模块由后续 P0 批次决定是否出现

应用中心工作区
  - 左侧筛选导航：全部应用、分类树/组织树、数量统计
  - 顶部检索条：当前范围、关键词搜索、关系筛选、状态筛选、排序、视图切换
  - 结果摘要：结果数量、当前筛选条件摘要
  - 应用展示区：卡片模式 / 列表模式
  - 页面状态：loading / empty / no_result / error / permission_denied
```

设计取舍：

```text
1. 借鉴参考图的“左侧模块导航 + 中间分类/组织树 + 右侧应用卡片网格”结构。
2. 不照搬参考图中的非 P0 模块菜单。
3. 不在本批实现创建、文件夹管理、回收站等动作，只保留后续操作位或不展示。
4. 不展示资源数量统计作为主信息，资源数量属于应用详情页 `P0-AC-011` 的重点。
5. 应用卡片以 P0-AC-002 要求的名称、图标、编码、描述、状态、负责人、发布时间、更新时间为核心。
```

## 5. 页面布局设计

### 5.1 桌面端布局

```text
┌──────────────────────────────────────────────────────────────────────────┐
│ 顶部栏：平台标识 / 当前租户或组织 / 当前用户 / 全局搜索预留               │
├──────────────┬──────────────────────┬────────────────────────────────────┤
│ 模块导航      │ 应用范围/分类筛选      │ 应用中心内容区                       │
│              │                      │                                    │
│ 应用中心 17   │ 全部应用              │ 顶部检索条：                         │
│              │ 分类 A                │ 搜索应用  关系  状态  分类  排序      │
│ 后续模块预留  │ 分类 B                │ [卡片/列表] [重置]                    │
│              │ 分类 C                │                                    │
│              │                      │ 结果摘要：共 N 个应用                 │
│              │                      │                                    │
│              │                      │ 卡片网格 / 列表表格                   │
└──────────────┴──────────────────────┴────────────────────────────────────┘
```

桌面端原则：

```text
1. 不使用营销式大 Hero。
2. 信息密度可参考 e-Builder，但视觉表现必须服务 P0 应用定位。
3. 左侧模块导航只展示 P0 已确认入口，不展示未设计的非 P0 能力。
4. 分类/组织树在本批只作为筛选导航，不提供新建、编辑、删除。
5. 筛选区保持紧凑，适合重复操作。
6. 应用卡片高度稳定，避免因描述长短造成跳动。
7. 列表模式适合管理者批量扫描。
```

### 5.2 移动端 H5 布局

```text
┌──────────────────────┐
│ 应用中心              │
│ 搜索框                │
│ 范围按钮  筛选按钮  排序 │
├──────────────────────┤
│ 应用卡片单列           │
└──────────────────────┘
```

移动端原则：

```text
1. 默认卡片单列。
2. 左侧模块导航和分类/组织树收纳到抽屉。
3. 操作按钮不挤压应用名称和状态。
```

## 7. 搜索设计

### 7.1 搜索入口

```text
组件：Input.Search
占位文案：搜索名称、编码、描述、负责人
触发方式：输入即过滤，或回车触发；真实后端联调时由 API 查询
```

### 7.2 搜索范围

必须覆盖：

```text
1. appName
2. appKey
3. description
4. ownerName
```

### 7.3 搜索状态

| 状态 | 页面表现 |
|---|---|
| 未输入 | 展示当前权限范围内全部应用。 |
| 有结果 | 展示匹配应用，并展示结果数量。 |
| 无结果 | 显示“暂无匹配应用”，提供清空搜索。 |
| 接口失败 | 显示错误提示和重试入口。 |

## 8. 筛选与排序设计

### 8.1 筛选条件

| 条件 | 选项 | 对应功能点 |
|---|---|---|
| 状态 | 全部、已发布、草稿、已停用 | `P0-AC-004` |
| 分类 | 全部分类、动态分类列表 | `P0-AC-004` |
| 关系 | 全部应用、我管理的、我使用的、我创建的 | `P0-AC-004` |

### 8.2 排序条件

| 排序 | 规则 |
|---|---|
| 最近更新 | `updatedAt` 倒序，默认。 |
| 创建时间 | `createdAt` 倒序。 |
| 最近发布 | `publishedAt` 倒序，未发布靠后。 |
| 应用名称 | 按中文名称升序。 |

### 8.3 组合规则

```text
1. 搜索、状态、分类、关系可以组合。
2. 任一条件变化后，结果数量必须同步更新。
3. 无结果时不清空筛选条件，保留用户上下文。
4. 重置按钮清空搜索、状态、分类、关系，并恢复默认排序。
5. 非法排序字段必须回退到最近更新。
```

## 9. 卡片模式设计

### 9.1 卡片内容

```text
顶部：图标 + 应用名称 + 状态标签
中部：描述摘要、编码、分类、负责人
底部：更新时间、发布时间
操作：详情、设计、运行
```

### 9.2 卡片规则

```text
1. 卡片高度固定或使用同一最小高度。
2. 描述最多两行。
3. 状态标签必须醒目。
4. 未发布应用的运行入口不可误导用户，应显示“未发布”或禁用。
5. 已停用应用的运行入口应显示“已停用”或禁用。
```

## 11. 权限表现

本批只处理页面级表现，不替代后端鉴权。

| 场景 | 前端表现 |
|---|---|
| 用户无 `app.view` | 展示无权限或空列表。 |
| 用户无某应用访问权限 | 该应用不出现在列表。 |
| 用户有 `app.view` 但无设计权限 | 设计入口隐藏或置灰。 |
| 用户有运行权限但应用未发布 | 运行入口禁用并提示未发布。 |
| 用户有运行权限但应用已停用 | 运行入口禁用并提示已停用。 |

## 12. 页面状态

| 状态 | 触发条件 | 设计表现 |
|---|---|---|
| loading | 首次加载或重新查询 | 骨架屏。 |
| ready | 成功加载且有数据 | 展示筛选区和应用结果。 |
| empty | 当前用户无应用 | 空状态 + 后续批次创建/模板入口预留。 |
| no_result | 搜索筛选无匹配 | 无匹配提示 + 清空筛选按钮。 |
| error | API 或 Mock Service 失败 | Alert + 重试。 |
| permission_denied | 无 `app.view` | 403 Result 或空列表说明。 |

## 13. 组件拆分建议

```text
AppListPage
  AppPlatformHeader
  AppModuleSidebar
  AppScopeTree
  AppHomeHeader
  AppSearchFilterBar
  AppResultSummary
  AppViewModeSwitch
  AppCardGrid
  AppCard
  AppListTable
  AppStatusTag
  AppEntryActions
  AppEmptyState
```

组件规则：

```text
1. AppListPage 负责拉取数据和组合状态。
2. AppPlatformHeader 和 AppModuleSidebar 只承载全局框架，不引入非 P0 功能。
3. AppScopeTree 只负责当前应用范围/分类筛选，不做分类增删改。
4. AppSearchFilterBar 只负责输入筛选条件。
5. AppCardGrid / AppListTable 只负责展示。
6. AppEntryActions 根据 app 状态和权限展示入口。
7. 组件不直接访问 localStorage，不直接调用底层数据库。
```
