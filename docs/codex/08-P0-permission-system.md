# 08-P0-permission-system.md

## 1. 文档目的

本文档用于定义 **企业级低代码平台 v1.2 P0 阶段的权限系统模块需求**。

权限系统是低代码平台从“可搭建工具”走向“企业级可交付平台”的关键基础能力。P0 阶段权限系统需要覆盖应用搭建、应用发布、运行访问、数据操作、字段控制、流程审批、导入导出、审计追踪等核心链路。

本文档面向产品、架构、前端、后端、测试、实施以及后续 AI 生成系统架构、数据库设计、API 文档、代码骨架、测试用例和开发任务拆解使用。

---

## 2. 模块定位

P0 阶段权限系统定位为：

> **面向企业内部管理应用的分层权限控制体系，支持平台级、应用级、对象级、数据级、字段级和流程节点级权限，保证业务可搭、IT 可控、数据可隔离、操作可审计。**

权限系统不是单一的菜单权限，也不是简单的角色授权，而是贯穿以下模块的统一安全控制层：

```text
组织/用户/角色 → 提供用户身份、组织结构、角色分组和上下级关系
应用中心 → 控制谁能创建、管理、设计、发布、访问应用
数据建模 → 控制谁能管理对象、字段、关系和模型发布
表单设计器 → 控制谁能设计表单，以及运行态字段可见/可编辑/必填
视图/台账 → 控制谁能查看、查询、新增、编辑、删除、导入、导出数据
流程引擎 → 控制谁能发起、审批、查看、撤回、作废和管理流程
发布运行时 → 在运行态执行统一鉴权，避免越权访问
模板中心 → 控制模板安装、导出、复制和二次编辑权限
审计日志 → 记录权限配置变更和被权限保护的关键操作
```

P0 阶段权限系统重点解决：

```text
1. 平台管理员可以管理组织、用户、角色和全局权限。
2. 应用管理员可以管理指定应用的设计、发布、成员和权限。
3. 普通用户只能访问被授权的应用、菜单、页面和数据。
4. 同一应用中，不同角色可以拥有不同对象操作权限。
5. 同一对象中，不同用户可以看到不同数据范围。
6. 同一条数据中，不同角色可以看到或编辑不同字段。
7. 流程不同节点可以配置不同字段权限。
8. 权限变更必须可审计、可追踪。
9. 运行态所有关键操作必须经过服务端鉴权。
```

## 3. 目标用户

| 用户角色 | 使用目标 |
|---|---|
| 平台超级管理员 | 管理平台级权限、组织、用户、角色、系统配置和审计策略。 |
| 租户/企业管理员 | 管理本企业范围内组织架构、用户、角色、应用授权和数据访问规则。 |
| 应用管理员 | 管理指定应用的成员、角色、对象权限、数据权限、字段权限和发布权限。 |
| 应用设计者 | 在授权范围内设计对象、表单、视图、流程、页面和看板。 |
| 实施/配置顾问 | 为客户配置应用权限、角色、数据范围和流程节点权限。 |
| 普通业务用户 | 访问被授权应用，提交数据，查看本人或授权范围内的数据。 |
| 审批人/流程处理人 | 在被分配的流程任务中查看表单、编辑允许字段、提交审批意见。 |
| 审计员/IT 管理员 | 查看权限变更、数据访问、导入导出和敏感操作日志。 |

## 4. P0 范围

P0 阶段权限系统必须支持以下能力。

### 4.1 身份主体

P0 支持以下授权主体：

```text
用户
角色
部门
部门及下级部门
应用内角色
流程节点处理人
系统内置角色
```

P0 不要求支持复杂用户组、岗位矩阵、外部协作者、临时授权审批流，但数据库和策略模型应预留扩展字段。

---

### 4.2 权限层级

P0 权限层级如下：

```text
平台级权限
应用级权限
菜单/页面级权限
对象级权限
数据级权限
字段级权限
流程级权限
流程节点字段权限
导入导出权限
模板权限
审计查看权限
```

---

### 4.3 平台级权限

P0 平台级权限至少包括：

| 权限项 | 说明 |
|---|---|
| 管理组织 | 创建、编辑、停用部门。 |
| 管理用户 | 创建、编辑、启用、停用用户。 |
| 管理角色 | 创建、编辑、删除角色，配置角色成员。 |
| 管理应用 | 查看和管理全部应用。 |
| 管理模板 | 管理系统内置模板和企业级模板。 |
| 查看审计日志 | 查看平台级操作日志和安全日志。 |
| 系统配置 | 管理平台基础配置。 |

P0 阶段平台级权限可先以系统内置角色承载，不要求复杂策略编辑器。

---

### 4.4 应用级权限

P0 应用级角色建议内置：

| 应用角色 | 权限说明 |
|---|---|
| 应用所有者 | 拥有应用全部管理、设计、发布、成员、权限和删除权限。 |
| 应用管理员 | 可管理应用配置、成员、权限、发布和运行数据。 |
| 应用设计者 | 可设计对象、表单、视图、流程、页面、看板，但不能删除应用。 |
| 应用使用者 | 可在运行端访问应用，并按对象/数据/字段权限操作。 |
| 应用只读者 | 只能查看被授权页面和数据，不能新增、编辑、删除。 |

P0 应用级权限包括：

```text
访问应用
管理应用基础信息
管理应用成员
管理应用权限
设计数据对象
设计表单
设计视图
设计流程
设计页面/看板
发布应用
停用应用
复制应用
删除应用
恢复应用
查看应用日志
```

---

### 4.5 菜单/页面级权限

P0 支持：

```text
应用菜单可见权限
页面可见权限
工作台入口可见权限
列表页入口可见权限
详情页入口可见权限
看板页入口可见权限
流程待办入口可见权限
```

P0 不要求做复杂页面组件级权限，但字段级权限和按钮级权限必须覆盖核心操作。

---

### 4.6 对象级权限

对象级权限用于控制用户对某个业务对象的操作能力。

P0 对象级权限至少包括：

| 操作权限 | 说明 |
|---|---|
| 查看 | 可查看对象数据列表和详情。 |
| 新增 | 可创建对象数据。 |
| 编辑 | 可编辑对象数据。 |
| 删除 | 可删除对象数据，P0 采用软删除。 |
| 作废 | 可将业务数据标记为作废。 |
| 导入 | 可通过 Excel 导入对象数据。 |
| 导出 | 可导出对象数据。 |
| 批量操作 | 可批量删除、批量作废或批量导出，P0 可按功能逐步开放。 |
| 管理对象 | 可维护对象字段、关系、状态和发布。 |

---

### 4.7 数据级权限

P0 数据级权限用于控制用户能看到哪些记录。

P0 支持以下数据范围：

| 数据范围 | 说明 |
|---|---|
| 仅本人数据 | 只能访问自己创建、提交或负责的数据。 |
| 本部门数据 | 可以访问所属部门的数据。 |
| 本部门及下级部门数据 | 可以访问本部门及下级部门的数据。 |
| 指定角色数据 | 可以访问指定角色成员创建或负责的数据。 |
| 指定用户数据 | 可以访问指定用户创建或负责的数据。 |
| 全部数据 | 可以访问当前应用/对象下全部数据。 |
| 条件规则数据 | 按字段条件过滤，例如合同类型、金额范围、区域、状态。 |

P0 数据权限必须支持与对象查询、详情访问、导出、流程查看、看板统计联动。

---

### 4.8 字段级权限

字段级权限用于控制字段在不同角色、不同场景下的可见和可编辑状态。

P0 字段级权限至少支持：

| 权限类型 | 说明 |
|---|---|
| 可见 | 用户可以看到字段。 |
| 不可见 | 用户不能看到字段，前端不展示，后端不返回。 |
| 只读 | 用户可以看到但不能编辑。 |
| 可编辑 | 用户可以编辑字段。 |
| 必填 | 在指定场景下提交时必须填写。 |
| 脱敏展示 | P0 可预留，建议对银行卡号、手机号等敏感字段后续增强。 |

字段级权限应用场景：

```text
新增表单
编辑表单
查看详情
审批表单
列表视图
导出数据
流程节点
```

---

### 4.9 流程权限

P0 流程权限包括：

```text
谁可以发起流程
谁可以审批任务
谁可以查看流程实例
谁可以撤回流程
谁可以作废流程
谁可以管理流程定义
谁可以查看流程日志
谁可以在某节点编辑某些字段
```

P0 流程权限必须与流程任务分配联动：

```text
只有当前任务处理人可以审批当前任务。
非当前任务处理人不能代替审批。
流程发起人可查看自己发起的流程。
应用管理员可查看本应用流程实例和日志。
节点字段权限优先影响审批表单展示与提交。
```

---

### 4.10 导入导出权限

P0 必须单独控制导入导出权限，不能简单等同于查看权限。

导入导出规则：

```text
拥有查看权限不代表拥有导出权限。
拥有新增权限不代表拥有导入权限。
导出数据必须受数据级权限限制。
导出字段必须受字段级权限限制。
导入字段必须受字段可编辑权限限制。
导入失败详情应只展示用户有权看到的字段。
所有导入导出操作必须记录审计日志。
```

---

### 4.11 审计权限

P0 支持审计日志查看权限。

审计权限分为：

```text
平台审计查看
应用审计查看
对象数据审计查看
流程审计查看
权限变更审计查看
导入导出审计查看
```

普通用户不应默认具备审计日志查看权限。

---

## 5. P0 不做范围

P0 阶段明确不做以下能力：

```text
1. 不做完整 ABAC 策略编辑器。
2. 不做复杂岗位矩阵权限。
3. 不做跨租户授权和跨企业协同授权。
4. 不做临时授权审批流。
5. 不做权限申请/审批中心。
6. 不做复杂数据脱敏规则引擎。
7. 不做字段级加密密钥管理。
8. 不做完整零信任安全体系。
9. 不做 OAuth2/SAML/OIDC 深度身份源集成，只预留接口。
10. 不做插件级权限沙箱，插件和在线开发属于 P3。
11. 不做细到页面组件内部每个元素的权限配置。
12. 不做会签、并行、加签、转交等高级流程权限。
```

## 5A. P0 必做清单详表（执行版）

文档版本：v1.2  
更新日期：2026-05-06  
适用范围：`08-P0-permission-system.md`  

本章节用于把权限系统从“能力描述”细化为可研发、可测试、可由 AI 后续生成权限模型、鉴权中间件、权限配置页面、数据库表、API 和测试用例的 P0 执行清单。权限系统是平台主干安全边界，所有运行态接口必须服务端鉴权。


### 5A.1 P0 功能点描述统一要求

本章节中的每一个 P0 功能点都必须满足以下描述规范，后续 AI 生成页面、API、数据库、测试用例和开发任务时必须直接引用功能编号。

| 描述项 | 要求 |
|---|---|
| 功能编号 | 使用 `P0-模块缩写-序号`，序号三位递增。 |
| 所属分类 | 标明该功能归属的业务分类，便于研发分包。 |
| 用户角色 | 标明主要使用者，不能只写“用户”。 |
| 业务目标 | 说明为什么需要该功能。 |
| 前置条件 | 说明功能执行前必须存在的数据、权限或状态。 |
| 输入内容 | 说明页面、接口或配置需要输入哪些字段。 |
| 处理逻辑 | 说明服务端、前端或运行时需要执行的关键逻辑。 |
| 输出结果 | 说明功能执行后产生什么数据、状态或页面变化。 |
| 权限要求 | 说明该功能需要经过哪些权限校验。 |
| 审计要求 | 说明是否需要写入审计日志以及记录内容。 |
| 异常处理 | 说明常见失败场景及系统反馈。 |
| 验收标准 | 说明测试可以如何判断该功能完成。 |

### 5A.2 P0 功能点优先级规则

| 优先级 | 含义 | 处理原则 |
|---|---|---|
| P0-Must | 没有该功能，主业务闭环不可运行。 | 必须随 P0 首版交付。 |
| P0-Should | 没有该功能，主业务闭环仍可运行，但交付体验明显下降。 | 原则上纳入 P0，资源紧张时可降级但必须保留入口。 |
| P0-Guardrail | 不是直接业务功能，但用于安全、审计、发布稳定性。 | 必须纳入 P0，不可后补。 |


### 5A.3 P0 功能分类总览

| 分类编号 | 分类名称 | 分类说明 | 是否 P0 必做 |
|---|---|---|---|
| PERM-C01 | 权限模型与角色 | 内置角色、自定义角色、权限动作。 | 是 |
| PERM-C02 | 平台与应用权限 | 控制平台管理和应用管理能力。 | 是 |
| PERM-C03 | 对象与功能权限 | 控制对象 CRUD、导入导出、设计操作。 | 是 |
| PERM-C04 | 数据权限 | 控制记录可见范围。 | 是 |
| PERM-C05 | 字段权限 | 控制字段可见、可编辑、必填、脱敏预留。 | 是 |
| PERM-C06 | 流程权限 | 控制发起、审批、查看、撤回、作废和节点字段权限。 | 是 |
| PERM-C07 | 运行时鉴权 | 所有运行态接口统一鉴权。 | 是 |
| PERM-C08 | 权限审计 | 权限变更、越权拒绝、敏感操作记录。 | 是 |

### 5A.4 P0 权限系统必做功能明细

#### P0-PERM-001 权限配置总入口

| 描述项 | 内容 |
|---|---|
| 所属分类 | PERM-C01 |
| 用户角色 | 平台管理员、企业管理员、应用管理员 |
| 业务目标 | 提供统一入口配置角色、应用、对象、数据、字段和流程权限。 |
| 前置条件 | 当前用户具备权限管理权限。 |
| 输入内容 | appId 可选、角色筛选、资源类型。 |
| 处理逻辑 | 根据上下文展示平台级权限或应用级权限；普通应用管理员只能管理授权应用。 |
| 输出结果 | 权限配置页面。 |
| 权限要求 | `permission.manage`。 |
| 审计要求 | 查看不审计，变更审计。 |
| 异常处理 | 无权限时隐藏入口或展示无权限页面。 |
| 验收标准 | 应用管理员可进入合同应用权限配置页。 |

#### P0-PERM-002 内置角色初始化

| 描述项 | 内容 |
|---|---|
| 所属分类 | PERM-C01 |
| 用户角色 | 系统、平台管理员 |
| 业务目标 | 初始化平台运行所需基础角色。 |
| 前置条件 | 租户创建或系统初始化。 |
| 输入内容 | tenantId。 |
| 处理逻辑 | 初始化平台超级管理员、企业管理员、应用管理员、应用设计者、普通用户、审计员等角色。 |
| 输出结果 | 内置角色记录。 |
| 权限要求 | 系统内部。 |
| 审计要求 | 初始化记录可写入系统日志。 |
| 异常处理 | 重复初始化需幂等。 |
| 验收标准 | 新租户创建后自动拥有基础角色。 |

#### P0-PERM-003 权限动作字典

| 描述项 | 内容 |
|---|---|
| 所属分类 | PERM-C01 |
| 用户角色 | 后端、前端、AI 生成器 |
| 业务目标 | 统一定义权限动作编码，避免各模块随意命名。 |
| 前置条件 | 系统启动或初始化。 |
| 输入内容 | 权限动作定义。 |
| 处理逻辑 | 至少覆盖 app/entity/field/form/workflow/release/data/audit/org/user/role 等资源。 |
| 输出结果 | permission_action 字典。 |
| 权限要求 | 系统内部维护。 |
| 审计要求 | 动作字典变更审计。 |
| 异常处理 | 未定义权限动作不得用于鉴权。 |
| 验收标准 | `entity.create`、`form.design`、`workflow.task.approve` 等动作可被统一引用。 |

#### P0-PERM-004 应用级成员与角色授权

| 描述项 | 内容 |
|---|---|
| 所属分类 | PERM-C02 |
| 用户角色 | 应用管理员 |
| 业务目标 | 控制谁能管理、设计、访问某个应用。 |
| 前置条件 | 应用存在，用户/角色存在。 |
| 输入内容 | appId、principalType、principalId、appRole。 |
| 处理逻辑 | 支持用户、部门、角色授权；授权为应用管理员、设计者、使用者、只读者。 |
| 输出结果 | app_member 或 resource_acl 记录。 |
| 权限要求 | `app.member.manage`。 |
| 审计要求 | 授权和取消授权必须审计。 |
| 异常处理 | 不可移除最后一个应用管理员。 |
| 验收标准 | 将法务角色授权为合同应用使用者后，法务用户可进入应用。 |

#### P0-PERM-005 平台级权限控制

### 5A.5 P0 权限系统完成定义 Definition of Done

```text
1. 平台、应用、对象、数据、字段、流程和发布权限均有明确权限动作。
2. 可以为用户、部门、角色配置应用成员和应用角色。
3. 可以配置对象查看、新增、编辑、删除、导入、导出权限。
4. 可以配置本人、本部门、本部门及下级、全部数据四类 P0 数据范围。
5. 可以配置字段可见、只读/可编辑、必填规则。
6. 流程发起、处理、查看、撤回、作废必须鉴权。
7. 所有运行态 API 必须经过服务端鉴权。
8. 字段权限必须同时作用于页面展示、接口返回和导出结果。
9. 权限配置变更和敏感导入导出必须审计。
10. 合同、报销、采购三个样板应用权限可直接使用并通过验收。
```

## 6. 核心概念

### 6.1 Principal 授权主体

授权主体是被授予权限的对象。

P0 授权主体包括：

```text
user：用户
role：全局角色
department：部门
app_role：应用角色
workflow_actor：流程处理人
system_role：系统内置角色
```

---

### 6.2 Resource 资源

资源是被保护的对象。

P0 资源类型包括：

```text
platform：平台
app：应用
menu：菜单
page：页面
entity：业务对象
field：字段
form：表单
view：视图
dashboard：看板
workflow：流程定义
workflow_instance：流程实例
task：流程任务
template：模板
audit_log：审计日志
file：附件
import_export_job：导入导出任务
```

### 6.4 Policy 权限策略

权限策略定义：谁可以对什么资源执行什么操作，以及在什么条件下执行。

P0 策略模型建议包含：

## 7. 权限模型总原则

### 7.1 默认拒绝原则

除系统内置超级管理员外，所有用户默认无权限。

```text
未授权应用不可见。
未授权菜单不可见。
未授权对象不可访问。
未授权字段不可返回。
未授权数据不可查询。
未授权操作不可执行。
```

---

### 7.2 最小权限原则

系统只授予用户完成工作所需的最小权限。

示例：

```text
合同申请人可以新增合同，但不能删除合同对象。
部门负责人可以审批本部门合同，但不能修改流程定义。
财务可以编辑付款字段，但不能编辑合同法务意见。
普通用户可以查看自己的报销单，但不能导出全部报销数据。
```

---

### 7.3 服务端强制鉴权原则

前端隐藏按钮和字段只是用户体验，不能作为安全边界。

P0 要求：

```text
所有 API 必须服务端鉴权。
列表查询必须服务端追加数据权限条件。
详情查询必须服务端校验记录访问权限。
数据写入必须服务端校验对象权限和字段权限。
流程处理必须服务端校验任务处理人权限。
导出必须服务端过滤无权数据和无权字段。
```

---

### 7.4 权限与发布版本一致原则

运行态应使用已发布版本权限，不应直接读取未发布草稿权限。

```text
设计态权限修改不会立即影响运行态。
权限配置随应用发布进入运行态。
已发布应用可回滚到历史权限版本。
流程实例应绑定发起时的流程版本和权限快照。
```

---

### 7.5 审计可追踪原则

关键权限相关操作必须记录审计日志：

```text
角色创建/修改/删除
用户加入/移出角色
应用成员变更
应用权限变更
对象权限变更
数据权限变更
字段权限变更
流程节点权限变更
导入导出权限使用
越权访问失败
```

## 8. 权限层级与优先级

P0 权限判断建议按以下层级执行：

```text
1. 用户是否有效、是否被停用。
2. 用户是否属于当前租户/企业。
3. 用户是否拥有应用访问权限。
4. 用户是否拥有页面/菜单访问权限。
5. 用户是否拥有对象操作权限。
6. 用户是否满足数据范围权限。
7. 用户是否满足字段级权限。
8. 如果是流程任务，用户是否为当前任务处理人或授权查看人。
9. 如果是导入导出，用户是否拥有专项导入导出权限。
10. 记录审计日志或鉴权失败日志。
```

冲突处理建议：

| 场景 | P0 处理建议 |
|---|---|
| 多个角色权限叠加 | 取并集。 |
| 字段权限冲突 | 更严格优先，不可见 > 只读 > 可编辑。 |
| 数据权限冲突 | 默认取并集，后续可支持更严格策略。 |
| 系统管理员 | 可绕过应用级限制，但仍需记录审计。 |
| 被停用用户 | 无论角色如何，均不能登录和访问数据。 |

## 10. 用户故事

### 10.1 平台管理员管理权限

作为平台管理员，我希望可以创建角色、分配用户和配置平台级权限，以便不同人员承担不同管理职责。

作为应用管理员，我希望可以给部门、角色或用户分配应用访问权限和设计权限，以便控制谁能使用或维护应用。

验收点：

```text
未授权用户看不到应用入口。
授权为应用使用者后可以访问应用运行端。
授权为应用设计者后可以进入应用设计态。
应用权限变更必须写入审计日志。
```

### 10.3 实施顾问配置对象权限

作为实施顾问，我希望可以为合同对象配置不同角色的查看、新增、编辑、删除、导入、导出权限，以便符合客户企业管理要求。

验收点：

```text
普通员工可新增合同申请。
法务角色可查看合同并填写法务意见。
财务角色可编辑付款相关字段。
普通员工不能删除合同数据。
```

---

### 10.4 业务管理员配置数据权限

作为业务管理员，我希望销售只能看自己的客户，部门负责人可以看本部门合同，财务可以看全部报销单，以便实现分层数据管理。

验收点：

```text
导出结果只包含授权范围内数据。
看板统计也应遵守数据权限。
```

---

### 10.5 应用设计者配置字段权限

作为应用设计者，我希望不同角色看到不同字段，审批节点只能编辑指定字段，以便保护敏感信息并保证流程规范。

验收点：

```text
合同金额可对普通员工隐藏或只读。
财务节点可以编辑付款字段。
法务节点可以编辑法务意见字段。
导出时无权字段不出现在导出文件中。
```

## 14. 权限业务规则

### 14.1 应用访问规则

```text
用户必须被授权应用访问权限，才可以看到应用入口。
应用停用后，普通用户不可访问，应用管理员可查看停用状态和日志。
应用删除进入回收站后，普通用户不可访问。
应用恢复后恢复原有权限配置。
```

---

### 14.2 对象访问规则

```text
用户访问对象列表前必须校验对象查看权限。
用户新增数据前必须校验对象新增权限。
用户编辑数据前必须校验对象编辑权限和数据范围权限。
用户删除数据前必须校验对象删除权限和数据范围权限。
用户导出数据前必须校验对象导出权限、数据范围权限和字段导出权限。
```

---

### 14.3 数据权限规则

```text
数据权限必须作用于列表、详情、导出、看板和流程查看。
数据权限必须由服务端拼接到查询条件中。
用户直接通过 URL 访问无权数据时，服务端必须拒绝。
数据权限不得只依赖前端过滤。
管理员查看数据也应记录审计日志。
```

---

### 14.4 字段权限规则

```text
字段不可见时，API 响应不应返回该字段值。
字段只读时，前端不可编辑，后端也拒绝写入。
字段可编辑仍需通过对象编辑权限和数据范围权限。
字段必填仅在对应场景生效。
字段权限必须同时影响表单、详情、列表和导出。
```

---

### 14.5 流程权限规则

```text
流程任务只能由当前处理人处理。
流程发起人可以查看自己发起的流程。
应用管理员可以查看本应用流程实例。
撤回仅允许发起人在流程未结束且规则允许时执行。
作废仅允许拥有作废权限的角色执行。
审批节点字段权限优先于普通编辑权限。
```

---

### 14.6 权限发布规则

```text
权限配置修改先进入草稿。
发布应用时生成权限版本快照。
运行态读取已发布权限快照。
应用回滚时权限快照同步回滚。
权限发布必须校验是否存在至少一个应用管理员。
```

## 15. 异常处理

### 15.1 无应用访问权限

场景：用户访问未授权应用。

处理：

```text
前端不展示应用入口。
通过 URL 直接访问时，服务端返回 403。
记录可选安全日志，避免日志噪音过大。
```

---

### 15.2 无对象操作权限

场景：用户点击编辑、删除、导出等操作，但无权限。

处理：

```text
前端隐藏或禁用按钮。
后端返回 403 和明确错误码。
不执行任何数据变更。
记录操作失败日志。
```

---

### 15.3 无数据访问权限

场景：用户通过详情 URL 访问无权记录。

处理：

```text
服务端返回 403 或资源不存在提示。
不返回记录内容。
不返回敏感字段。
记录访问失败日志。
```

---

### 15.4 字段越权写入

场景：用户提交表单时包含无权编辑字段。

处理：

```text
服务端拒绝保存无权字段。
建议整个请求失败，并返回字段级错误。
不得静默更新无权字段。
记录越权写入日志。
```

---

### 15.5 权限配置冲突

场景：用户多个角色字段权限冲突。

处理：

```text
字段权限按更严格优先。
数据权限按并集处理。
对象操作权限按并集处理。
权限预览应提示权限来源。
```

---

### 15.6 角色或部门被删除

场景：权限策略引用的角色或部门被删除/停用。

处理：

```text
角色停用后不参与权限计算。
部门停用后需提示相关权限策略异常。
删除前应提示被引用情况。
历史审计记录保留名称快照。
```

## 22. 验收标准

### 22.1 平台级验收

```text
1. 超级管理员可以创建角色、配置成员并启用/停用角色。
2. 停用用户不能登录和访问任何应用。
3. 普通用户默认看不到未授权应用。
4. 权限配置变更必须写入审计日志。
```

---

### 22.2 应用级验收

```text
1. 应用所有者可以配置应用成员和应用角色。
2. 应用设计者可以进入设计态，但不能管理平台级配置。
3. 应用使用者只能进入运行态。
4. 应用只读者不能新增、编辑、删除业务数据。
5. 应用至少保留一个应用所有者。
```

---

### 22.3 对象权限验收

```text
1. 有查看权限的用户可以查看对象列表。
2. 无查看权限的用户无法访问对象列表和详情。
3. 有新增权限的用户可以创建数据。
4. 无编辑权限的用户不能修改数据，即使通过接口提交也必须被拒绝。
5. 有删除权限的用户可以软删除数据，无权限用户不能删除。
```

---

### 22.4 数据权限验收

```text
1. 普通员工只能看到本人创建的合同、报销或采购申请。
2. 部门负责人可以看到本部门数据。
3. 财务角色可以看到授权范围内的全部报销数据。
4. 详情访问必须遵守数据权限。
5. 导出和看板统计必须遵守数据权限。
```

---

### 22.5 字段权限验收

```text
1. 不可见字段在表单、详情、列表和导出中都不可见。
2. 只读字段不能被前端编辑，也不能被接口更新。
3. 审批节点可以配置节点字段权限。
4. 财务节点可以编辑付款字段，其他节点不可编辑。
5. 字段越权写入必须被服务端拒绝并记录日志。
```

---

### 22.6 流程权限验收

```text
1. 只有当前审批任务处理人可以提交审批。
2. 非处理人通过接口提交审批必须失败。
3. 发起人可以查看自己发起的流程。
4. 应用管理员可以查看应用内流程日志。
5. 撤回和作废必须受专项权限控制。
```

---

### 22.7 导入导出验收

```text
1. 有查看权限但无导出权限的用户不能导出数据。
2. 导出结果只包含用户有权访问的数据。
3. 导出结果不包含用户无权查看的字段。
4. 导入时无权编辑字段不能被写入。
5. 导入导出操作必须写入审计日志。
```

## 25. P0 权限系统总体验收清单

P0 权限系统完成后，应满足：

```text
平台管理员能管理角色和成员。
应用管理员能配置应用成员和应用角色。
不同用户登录后只能看到被授权应用。
不同角色在同一应用内拥有不同对象操作权限。
不同用户看到的数据范围不同。
不同角色看到和编辑的字段不同。
流程审批任务只能由当前处理人处理。
导入导出必须单独授权并受数据/字段权限限制。
权限修改随应用发布进入运行态。
草稿权限不影响已发布应用。
应用回滚时权限版本同步回滚。
权限变更和越权访问可审计追踪。
合同、报销、采购三个样板应用都能通过权限系统实现基本隔离和控制。
```
